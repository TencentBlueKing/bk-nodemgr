## [Version: v3.0.1-alpha.122] - 2026-11-27

Full Changelog: [v3.0.1-alpha.121...v3.0.1-alpha.122](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.121...v3.0.1-alpha.122)

> Important notes

- Backend and Relay now reuse a local service for WMI execution. When using WMI, ensure that a loopback listening port is available within the configured range, `28160–28169` by default. These ports do not need to be exposed externally.

**Release scope**

- Backend/Control Plane: WMI command execution and file transfer.
- Application/Frontend: Read-only scheduled task and system configuration pages under platform management, with supporting query APIs.
- Installer/Deployment: Local WMI port and tracing configuration.

**New features**

- The scheduled task page supports querying periodic workflows in the current tenant, filtering and paginating scheduling configurations, and viewing execution history, instance states, and step logs. The page and new Application APIs are read-only; they do not provide enable, disable, edit, or retry operations.
- The system configuration page displays an allowlisted view of business configuration loaded at startup by the responding Backend instance, including tenant mode, deployment environment, IAM switches, default event Data IDs, automatic creation settings for the default direct Network Unit, and GSE installation defaults. It excludes credentials, connection endpoints, and internal observability settings. It does not support online changes or represent configuration consistency across replicas or the actual state of target hosts.

**Improvements**

- WMI command execution and file transfer reuse an embedded service per process instead of initializing Python for every call. Requests for different targets can run concurrently, while requests for the same target are serialized. Tracing and request metrics are also added.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.

**Component dependencies and upgrade prerequisites**

- To use the new read-only pages, update Application and Frontend together and use a Backend that provides the corresponding query APIs. Access retains the existing login authentication and `system_access` check. Scheduled task queries require `platform_manage` on `platform_resource/scheduler_workflow`; system configuration queries require `platform_manage` on `platform_resource/system_config`.
- WMI callers support Linux amd64 and arm64 and must be allowed to execute local temporary files. Target Windows hosts still require WMI/DCOM and SMB access.
- Backend and Relay can configure local ports through `wmi.portRange`; the Backend Helm value is `backend.config.wmi.portRange`. Ports must be within 1–65535, with the end port no lower than the start port. The embedded WMI service cannot start if all ports in the range are unavailable.
- WMI `traceSampleRate` defaults to `0`. With Helmfile and Gateway enabled, the Backend WMI sample rate is set to `1` when not explicitly configured; explicit values take precedence.
- A WMI request timeout or cancellation closes that request's connections; it does not imply that the remote command was not executed. Failed executions are not automatically retried. Check the remote result before resubmitting. If the embedded service exits, the next call starts it again without replaying the failed request.
