## [Version: v3.0.1-alpha.111] - 2026-11-13

Full Changelog: [v3.0.1-alpha.110...v3.0.1-alpha.111](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.110...v3.0.1-alpha.111)

> Important notes

- Node, V3 Plugin, and legacy V2 Plugin Installers now require the complete working directory through `--work_dir` instead of deriving it from `--base_work_dir`. Upgrade the Control Plane and Installers together. Custom scripts that invoke an Installer directly must also update their arguments.

**Release scope**

- Backend/Control Plane: Per-user working directory isolation for node and plugin operations, legacy V2 plugin process synchronization, and a tenant-context fix in the File service.
- Application/Frontend: Batch entry of private IPv4/IPv6 addresses for new host installations.
- Installer/Deployment: Installer working directory arguments and directory permission management.

**New features**

- The new installation page accepts multiple private IPv4/IPv6 addresses separated by spaces, commas, or line breaks, creating one host per IP. This entry point is not available for reinstallation or upgrade.
- Adds process synchronization for legacy V2 plugins: trigger alive or stopped process synchronization for selected hosts or all hosts, and run stopped-process synchronization automatically every 10 minutes. APIs return a `trigger_id`; check workflow records for execution results.
- Installer working directories are isolated by execution channel. SSH/WMI/manual installations use the login user's directory, sudo installations use a separate directory, and GSE-channel operations use the operate user's directory, reducing cross-user file ownership conflicts.

**Improvements**

- Process synchronization preserves confirmed results from successful hosts instead of discarding the entire batch when some hosts fail or time out. Unconfirmed targets are not treated as stopped.

**Bug fixes**

- Fixes the File service querying its current GSE Endpoint under a business tenant in multi-tenant mode. The lookup now uses the system tenant, preventing direct-network-area host lookup failures from disrupting file transfers.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- Adds four legacy V2 plugin process synchronization APIs without changing existing API paths or request/response structures. For Installer command-line compatibility, see the `--work_dir` change in Important notes.

**Component dependencies and upgrade prerequisites**

- Ensure that the Installers distributed by the Control Plane match this release; do not mix in older Installers. Update custom invocations from `--base_work_dir` to a complete `--work_dir` that includes the user-isolation segment.
- Environments using API Gateway must synchronize this release's resources before calling the new synchronization APIs. Synchronization is asynchronous; a successful API response does not mean process states have been synchronized.
