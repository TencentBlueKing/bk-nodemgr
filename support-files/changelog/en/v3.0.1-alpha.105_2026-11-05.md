## [Version: v3.0.1-alpha.105] - 2026-11-05

Full Changelog: [v3.0.1-alpha.104...v3.0.1-alpha.105](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.104...v3.0.1-alpha.105)

> Important notes

- Plugin installation and upgrade APIs remove `plugin[n].config_template_name` and automatically deploy all main configurations from the target release package. Remove this parameter from client requests and use the separate sub-configuration API for sub-configurations. Debug requests retain this parameter only for additional sub-configuration templates; specifying a main template name causes the task to fail.
- Installation and upgrade requests also renumber the Protobuf fields for `custom_config_context` and, for installation, `custom_spec`, making binary messages incompatible with older definitions. Upgrade Backend and Application together, regenerate affected clients, and synchronize API Gateway resources. Do not mix old and new Protobuf definitions.

**Release scope**

- Backend/Control Plane: Automatic plugin main configuration deployment, persisted sub-configuration composition options, topology request definitions, and CMDB error messages.
- Application/Frontend: Environment-specific platform resources, configuration policy option descriptions, and Agent/Proxy package upload errors.
- Installer/Deployment: Application settings for Helm, Helmfile, and Docker Compose, plus FileProxy configuration policy options.

**New features**

- Proxy configuration policies add `file.bittorrent.bind_ip` for FileProxy BT listener binding, accepting an IP address or network interface name. The option is disabled by default and has a preset value of `0.0.0.0`.
- Application `front.bkSharedResBaseJSURL` loads shared platform settings such as the logo, title, and footer per deployment environment without rebuilding Frontend. Leaving it empty uses the default platform settings.
- API Gateway resources add nine existing OpenNodeAgent APIs, two node operation history APIs, and plugin configuration file listing and sub-configuration removal APIs. Existing API permission settings remain unchanged.

**Improvements**

- V3 plugin installation, upgrade, and debugging, and legacy V2 plugin Ensure deployment automatically load all main configuration templates from the release package, replacing the fallback that added only the first main template when the configuration list was empty. Packages without main templates do not generate additional main configurations.
- Plugin deployment records can persist the target sub-configuration plugin, management set, templates, render variables, and variable mappings for the source plugin's bind IP and port, independently of source plugin configurations. This release adds persistence only, not a new sub-configuration composition execution entry point.
- Configuration policy options display Chinese and English hover descriptions. OpenNodeAgent adds Proto/Swagger descriptions for existing open APIs, without adding runtime routes or node operations.

**Bug fixes**

- Corrects topology graph-node query request definitions so API Gateway schemas and Frontend clients no longer use the response structure as the request structure.
- Agent/Proxy package upload failures display detailed backend errors in the upload card and notification. Fixes clipped long messages and missing failure state after network errors.
- When an inner IP already exists in the CMDB default Network Area (cloud area 0), the error explicitly advises reusing the existing host or cleaning up the conflicting record first. CMDB conflict validation rules are unchanged.
- Fixes notice text not remaining left-aligned. Frontend plugin installation and upgrade requests also remove `config_template_name`.

**Agent / Plugin / Package compatibility**

- This release does not change the Agent installer or plugin package formats. Automatic main configuration deployment requires correct main configuration markers in the release package; it does not modify template markers in previously imported packages.
- Historical plugin deployment records without sub-configuration composition options are read with empty options and are not backfilled. Previously lost or overwritten configuration contents are not restored.

**Component dependencies and upgrade prerequisites**

- The alpha.104 index requirements for same-named main and sub-configurations still apply: back up existing `process_config_<tenantID>` collections, verify successful creation of the four-field unique index including `data.is_main_config`, and then remove the old three-field unique index, which is not deleted automatically. Check and repair historical records with missing main/sub markers first. Once same-named main and sub-records exist, do not directly restore the old index or revert to older name-only configuration handling.
- Platform resource configuration requires matching Application and Frontend updates. Use `application.config.front.bkSharedResBaseJSURL` in Helm/Helmfile or `BK_NODEMGR_APPLICATION_SHARED_RES_BASE_JS_URL` in Docker Compose, and provide a shared resource URL accessible to browsers.
- The new FileProxy option requires an updated Application configuration policy list and Frontend. Environments overriding the built-in list through `application.config.configPolicyOption.proxyOption` or custom files must add the option to their list. Saving a policy does not automatically reconfigure existing Proxy nodes; deploy the corresponding configuration for it to take effect.
