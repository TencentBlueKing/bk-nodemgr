## [Version: v3.0.1-alpha.82] - 2026-09-08

Full Changelog: [v3.0.1-alpha.81...v3.0.1-alpha.82](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.81...v3.0.1-alpha.82)

> Important notice

- Release metadata, BKRepo directories, and package download paths are now tenant-isolated. Upgraded services no longer fall back to the old shared release collections. Environments with existing packages must confirm a data migration plan before upgrading; upgrading services alone does not preserve access through the old paths.
- Before upgrading or rolling back, stop submitting new tasks and wait for in-flight tasks to finish. Switch Backend, File Service, Relay, and installer together to avoid mixing old and new download paths, package receipt notifications, and plugin temporary directories.

**Release scope**

- Agent / Proxy: Installation downloads, Relay file transfers, and default port handling.
- Plugin: Tenant-specific enablement and separate v2/v3 temporary data.
- Package: Tenant-isolated storage, certificate package imports, and upload experience.
- Backend/Control Plane: Package management, task details, and execution log pages.
- Installer/Deployment: Plugin temporary directory changes and IAM v4 resource type migration tools.

**New features**

- Enabling a plugin creates its default plugin only for the current tenant instead of all tenants, allowing tenants to manage enablement independently.
- Certificate `.tgz` packages can now place certificate files at the archive root. Published packages use a consistent `cert/` directory structure.
- The IAM v4 migration tool now registers and renames four resource types, preserving the network area/node and package type/package parent-child relationships, with `--dry-run` support.

**Improvements**

- Package metadata and BKRepo origin, release, and export files are isolated by tenant. Installation download URLs carry a tenant path.
- Relay installation package caching supports restart recovery, expiration cleanup, and capacity configuration. Adjusted timeouts and retries for key installation steps to improve batch installation stability.
- Added confirmation before leaving an edited package upload form and an import format FAQ for Agent, Proxy, Plugin, certificate, and tool packages.

**Bug fixes**

- Fixed Relay temporary file conflicts during concurrent transfers, cache integrity validation, and message ACK waiting.
- Fixed Plugin v2/v3 tasks overwriting each other's packages, configurations, default logs, and status files during concurrent execution.
- Fixed cross-page selection and IP copying in task details, execution log navigation and filtering, and notifications that could not be dismissed.
- Proxy reinstallation applies the installation source selected in advanced options to every row. Unspecified or zero Relay ports use callback port `28302` and download port `28303`.

**Agent / Plugin / Package compatibility**

- Certificate packages still support the `cert/` directory, but packages mixing certificate files at the root and under `cert/` are rejected. Agent / Proxy and Plugin package formats are unchanged.
- Plugin temporary data moves to `data/plugin/v2` and `data/plugin/v3`; deployment and working directories are unchanged. Old shared temporary directories are not read automatically. Explicitly shared `log_dir` paths and conflicts between same-version tasks for the same plugin are outside this isolation change.
- Relay package receipt notifications now carry a file list and MD5 values. New Relays reject packages without verification information; do not mix old and new Backend/Relay components.

**Component dependencies and upgrade prerequisites**

- Release collections change from `release_{type}` to `release_{type}_{tenantID}`, BKRepo directories gain a `/{tenantID}/` prefix, and File Service download routes change to `/{tenant_id}/api/v3/...`. Update download callers and forwarding rules, and validate package queries, downloads, and exports for each tenant.
- **To be confirmed**: Tenant ownership, migration steps, and rollback procedures for existing release metadata and BKRepo files. Confirm and validate the plan before upgrading.
- Plugin rollback also requires coordinated Backend and installer rollback, with packages and configurations transferred again to the old paths.
- Run `--dry-run` before using the IAM v4 migration tool. Ancestor-chain conflicts stop migration, and completed operations are not rolled back automatically. The tool still does not migrate actions, roles, or grants; configure and validate permissions separately before enabling IAM v4.
