## [Version: v3.0.1-alpha.104] - 2026-11-02

Full Changelog: [v3.0.1-alpha.103...v3.0.1-alpha.104](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.103...v3.0.1-alpha.104)

> Important notes

- Helm deployments now use `common.logPath` for Application, Backend, and File logs. Its default changes from `/bk-nodemgr/logs` to `/bk-nodemgr/log`; component-level `config.log.dir` settings no longer take effect. Migrate custom log directories to `common.logPath` and adjust mounts and external collection paths accordingly.
- Deploy Policies with `ensure_absent=true` no longer follow forward deployment behavior. Reverse cleanup is not implemented: reverse policies containing specs return an error during execution or preview calculation, also preventing related forward policies in the same calculation from proceeding. Check enabled policies before upgrading; restore the field to `false` when forward deployment is required. Do not use it to uninstall plugins or delete configurations.
- Update custom installation/upgrade scripts: adminclient `bkapp code/secret` now requires a credential name (`iamv3`, `iamv4`, or `apigw-sync`). `init_package.py` removes `--jwt-key` and `--expire-hours`; adminclient now issues JWTs from File configuration with a fixed 24-hour lifetime. The standalone `jwt-generator` is no longer provided.
- Existing three-field unique indexes on `process_config_<tenantID>` collections are not removed automatically and still prevent same-named main and sub-configurations from coexisting. Before using this capability, back up data, verify that the four-field unique index including `data.is_main_config` has been created successfully, and then remove the corresponding old three-field unique index. Once same-named main and sub-records exist, the old unique index cannot be restored directly, and older name-only configuration handling must not be relied on.

**Release scope**

- Backend/Control Plane: Deploy Policy direction handling, plugin deployment preparation queries, and distinguishing same-named main and sub-configurations.
- File: Duplicate configuration template validation for V3, legacy V2, and V2 external plugin packages.
- Installer/Deployment: Unified Helm log directories, optional BlueKing log collection configuration, adminclient credential resolution, initial package imports, and IAM/API Gateway synchronization.
- Frontend: Current Agent/Proxy out-of-band settings, console-host selection, and pagination.

**New features**

- Helm adds `bkLogConfig.enabled`, disabled by default. Enabling it creates `BkLogConfig` resources for standard output and container file logs, collecting timestamped System/Business INFO log files.

**Improvements**

- Plugin deployment preparation reads hosts and plugins in batches and deduplicates default-version and release metadata queries within each request, reducing repeated queries during batch deployment.
- The Agent/Proxy out-of-band settings table loads current settings, displays console-host IPs and selection state, and retains existing custom out-of-band protocols.
- adminclient JWT issuance and application credential retrieval now support both KMS and plaintext deployments. Initial package imports and Helm sync Jobs use this shared entry point. Service configuration discovery supports both Helm `*_conf.yaml` and Docker Compose `bk-nodemgr-*.yml` files.

**Bug fixes**

- Fixes stale console-host selector topology after changing the top-level business selection. The IP selector now defaults to 10 items per page.
- Fixes `ensure_absent=true` entering forward deployment calculation; unsupported reverse operations now fail explicitly.
- Fixes collisions between same-named main and sub-configurations during template matching, deployment record updates, and policy calculation. Sub-configuration removal now targets only sub-configuration files and records, preserving same-named main configurations.

**Agent / Plugin / Package compatibility**

- This release does not change the Agent installer, plugin package formats, or package version requirements.
- Main and sub-configuration templates may share a name within a platform. V3, legacy V2, and V2 external plugin package imports now reject duplicate template names within the same type; correct duplicate declarations before importing again.
- Configuration records retain the existing `is_main_config` field. Previously overwritten content is not restored automatically, and missing main/sub markers are not backfilled. Check and repair affected historical records against their actual configuration type before performing configuration operations.

**Component dependencies and upgrade prerequisites**

- Displaying current settings in Frontend requires the existing Agent/Proxy out-of-band field query APIs. Use accompanying Backend/Application versions that provide these APIs, introduced in `v3.0.1-alpha.103`, or later.
- Before enabling `bkLogConfig.enabled`, install the `BkLogConfig` CRD supporting `bk.tencent.com/v1alpha1` and its log collection service, and set `bkLogConfig.dataId` to the target collection Data ID. Leave this feature disabled when not in use.
- JWT-authenticated initial package imports and Helm IAM/API Gateway synchronization require matching images that provide the updated `bk-nodemgr-adminclient`. For manual imports, make this binary executable and provide File configuration; use `--config-file` explicitly for nonstandard configuration filenames.
- In KMS mode, credential resolution requires a readable global envelope and `BK_NODEMGR_KMS_PRIVATE_KEY_GLOBAL`; decryption failures do not fall back to plaintext. In plaintext mode, JWT authentication requires a nonempty `<server>Server.jwtServerConfig.symmetricKey`. IAM sync credentials come from Backend `iamV3/iamV4.appCode/appSecret`; API Gateway sync credentials come from the Job environment variables `BK_APP_CODE` and `BK_APP_SECRET`, injected through `apigwSync.extraEnvVars`.

**Known issues**

- If current-setting queries fail, the out-of-band table remains available for submission but current fields may be empty. If a cross-page host query is interrupted, only hosts already loaded are displayed. Check settings and the host scope before submitting, and reload after a failure to avoid overwriting existing settings with empty fields or omitting target hosts.
