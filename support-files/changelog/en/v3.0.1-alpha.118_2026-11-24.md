## [Version: v3.0.1-alpha.118] - 2026-11-24

Full Changelog: [v3.0.1-alpha.117...v3.0.1-alpha.118](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.117...v3.0.1-alpha.118)

> Important notes

- The File requirement transfer request changes Protobuf field numbers. Integrations using binary Protobuf must upgrade clients together with the server. HTTP JSON request fields remain unchanged.

**Release scope**

- Backend/Control Plane: Plugin group queries, business visibility filtering, the File transfer protocol, and server-side temporary file isolation.
- Application/Frontend: Plugin list filtering by group.
- Installer/Deployment: Temporary file isolation for WMI installation.

**New features**

- The plugin list supports selecting multiple groups, with the `default` group selected initially. Available groups refresh when switching businesses, and changing the group filter restarts the query from the first page.
- Adds distinct plugin group queries through application-state and user-state APIs. Results respect the current tenant and the caller's authorized business scope, include plugins not yet installed on hosts, and are independent of list pagination.

**Bug fixes**

- Fixes plugin list and count queries dropping business visibility conditions, restoring filtering according to the existing business visibility rules.
- Fixes temporary directory paths being overwritten through shared state during concurrent calls, isolating temporary file directories for operations such as WMI installation and file export.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- Backend plugin requirement file management includes protocol definitions only in this release; callable management and transfer endpoints are not provided.
- The File requirement transfer request changes Protobuf field numbers: `target_dir` moves from `3` to `2`, and `target_host_id` moves from `4` to `3`. HTTP JSON field names remain unchanged; binary Protobuf encoding and decoding are incompatible with the previous field numbers.

**Component dependencies and upgrade prerequisites**

- Upgrade Backend, Application, and Frontend together when using plugin group filtering. Group queries retain `system_access` and `plugin_view` permission checks and do not expand business authorization scope.
- Before calling the new group query APIs through API Gateway, separately import and publish the corresponding gateway resources and configure invocation grants. Upgrading services does not automatically expose gateway endpoints.
- Integrations using binary Protobuf encoding or decoding for File requirement transfer messages must regenerate clients and upgrade them together with the server, without mixing old and new field numbers.
