## [Version: v3.0.1-alpha.117] - 2026-11-23

Full Changelog: [v3.0.1-alpha.116...v3.0.1-alpha.117](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.116...v3.0.1-alpha.117)

> Important notes

- Scheduled workflow queries, enable, and disable operations now require `platform_manage` on resource type `platform_resource` with resource ID `scheduler_workflow`. Synchronize the IAM V3 or V4 model and configure the corresponding grants when upgrading; `system_access` alone no longer grants access.
- The built-in MCP catalog is now synchronized and enabled through `apigwSync.mcp.enabled=true`, which defaults to disabled. Deployments that previously inherited the default catalog using only `ENABLE_SYNC_MCP_SERVERS=true` must migrate to the new switch or explicitly retain complete stage MCP definitions and their statuses. Upgrade the Chart and apigw-sync image together.
- Built-in mode enables `topo`, `execution`, and `system-diagnosis` for stages without an explicit `mcp_servers` setting. Global settings queries return raw database values shared across tenants, without redaction, and may include sensitive custom settings. Grant access only to approved internal maintenance applications and personnel, and restrict recording and forwarding of results.

**Release scope**

- Backend/Control Plane: Historical installation parameter queries, scheduler permissions and execution diagnostics, and read-only global settings queries.
- Application/Frontend: Prefilling new installation forms from Agent / Proxy installation history.
- Installer/Deployment: The MCP product catalog, synchronization switch and stage overrides, IAM platform management models, and Helm deployment and upgrade documentation.

**New features**

- Agent / Proxy installation task details allow selecting historical operations to prefill a new installation form with recoverable parameters. After users review and complete the parameters, the normal installation flow creates an independent new task; it does not retry or modify the historical task.
- Scheduled workflow diagnostics support operation, execution instance, step log, and extra execution log queries, with drill-down into a dispatch instance's direct child operations. Both application-state APIs and user-state read-only diagnostic endpoints retain tenant and task-chain ownership checks.
- Adds global settings list queries with pagination, name filtering, and counting through an application-state API and a user-state `system-diagnosis` MCP tool. Queries return only stored database values, do not fill defaults or represent the configuration currently effective in a process, and do not provide updates or deletion.
- The `topo` and `execution` MCP servers support personal token clients. Personal/public OAuth clients remain disabled for `system-diagnosis`; personal tokens do not replace gateway invocation grants or user business permissions.
- Adds a user-facing execution troubleshooting Skill for querying node and plugin tasks, instances, and logs through the execution diagnostics MCP or corresponding user-state APIs. It does not retry, terminate, or perform other mutations.

**Improvements**

- Separates the MCP product catalog from stage configuration. An explicit non-empty `mcp_servers` list fully overrides the built-in catalog without field merging; an explicit `[]` only skips synchronization for that stage and does not delete or disable existing MCP servers. Disabling an existing server requires a complete definition with `status: 0`.
- Expands Helm installation, upgrade, rollback, and versioned values migration documentation, including Hook synchronization side effects and persistent-data recovery boundaries.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- Historical installation prefill does not copy passwords, private keys, credential-vault IDs, or deployment Tokens. Credentials and permission checks still follow the normal installation flow. Historical records are not complete request snapshots: missing fields such as internal IPv6 addresses must be completed, and unavailable or conflicting business, Network Area, Network Unit, and target-version selections must be reviewed. Target versions are not automatically replaced with the latest version.
- Scheduler diagnostics cover only task chains associated with the current trigger whose records have not been cleaned up, not a complete historical archive. An enabled schedule or a successful parent instance does not imply successful child execution.

**Component dependencies and upgrade prerequisites**

- Upgrade Backend, Application, and Frontend together when using historical installation prefill, so the new pages can reach the upgraded parameter query API.
- Enable and synchronize IAM V3 or V4 before providing system diagnostics, and review existing application grants and wildcard platform resource grants. Scheduling uses `scheduler_workflow`; global settings require a separate grant on `global_settings`. Do not expose these endpoints with IAM business authorization disabled.
- Before using MCP, publish the required user-state gateway resources and configure application, user, and resource invocation permissions through the existing process. The new switch requires `spec_version: 2` and takes precedence over the old MCP synchronization environment variable, but does not automatically enable the synchronization Job or change release policies. Explicit catalogs do not automatically acquire new tools. See the [API Gateway synchronization guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.117/docs/faq/apigw-sync.md) for migration and authorization requirements.
- Follow the [upgrade guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.117/install/helm/bk-nodemgr/UPGRADE.md) to merge environment overrides and back up data before a Helm upgrade. Helm rollback does not undo completed changes in MongoDB, BKRepo, IAM, or the gateway.
