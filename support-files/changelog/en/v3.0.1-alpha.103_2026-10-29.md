## [Version: v3.0.1-alpha.103] - 2026-10-29

Full Changelog: [v3.0.1-alpha.102...v3.0.1-alpha.103](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.102...v3.0.1-alpha.103)

> Important notes

- Agent/Proxy out-of-band update APIs move to `/api/v3/node/ops/update_fields/agent` and `/api/v3/node/ops/update_fields/proxy`. The previous `/api/v3/node/{agent,proxy}/update_ops_fields` paths are removed. Integrators must update client paths and synchronize API Gateway resources.
- Basic System APIs and Open APIs now check `system_access` after identity verification. IAM callbacks retain their independent Basic Auth and are exempt from this check. Existing functional and resource permission checks remain independent.

**Release scope**

- Backend/Control Plane: Out-of-band operation history, current-field queries, the user-state Open API entry, and IAM model updates.
- Plugin/Package: Custom run and data directories for legacy V2 compatibility installation; cached release metadata reads.
- Installer/Deployment: KMS-based JWT signing for initial package import, with the required Helm Job secret mounts and environment variables.
- Frontend: Out-of-band operation history and details, an improved Network Area creation guide, and corrected console-host selection scope.

**New features**

- Out-of-band management adds Agent/Proxy update history with the operator, time, node role, and host-setting snapshots. History supports filtering by business scope, operation ID, operator, and time.
- Adds current out-of-band field queries at `/api/v3/node/ops/list_fields/agent` and `/api/v3/node/ops/list_fields/proxy`, protected by the corresponding node-view permissions. If any requested host does not exist, has been deleted, or belongs to another tenant, the entire request fails with a parameter error instead of returning partial results. Successful responses include all deduplicated target hosts.
- Backend adds the `/api/v3/open` user-state API entry for accessing node, plugin, topology, package, and other APIs through API Gateway user authentication.
- adminclient adds `jwt_token <service> <server>` to sign tokens using service JWT keys from the KMS global envelope. Initial package import can use this capability automatically.

**Improvements**

- Release metadata reads use a short-lived cache and coalesce concurrent identical queries. Release metadata and default-version changes may take approximately one minute to appear in affected queries.
- HTTP tracing records each actual request attempt and its errors separately to distinguish retries. Server-side tracing skips HEAD requests.
- After creating a Network Area, the guide opens that area's Network Unit configuration; users with creation permission are taken directly to the creation panel.

**Bug fixes**

- Fixes the out-of-band console-host selector not respecting the businesses selected in the top-level selector.
- Updates the Go toolchain to `1.26.10` and updates Excelize and related dependencies, addressing Excelize `CVE-2026-107211`.

**Agent / Plugin / Package compatibility**

- Legacy V2 compatibility installation accepts final directory paths through Backend `gseDeployConfs[*].pluginCustom.v2RunDir` and `v2DataDir`. Empty values retain the existing directory rules. Regular V3 installation does not use these settings.
- Compatibility installations with the same `generation` and `osType` share the configured directories; no environment or plugin directory suffix is appended. Avoid conflicting filenames in the shared data directory. Configuration changes do not migrate directories for already-deployed plugins.

**Component dependencies and upgrade prerequisites**

- Coordinate Backend, Application, Frontend, and API Gateway resource updates for the out-of-band API migration to prevent calls to removed paths.
- Before upgrading Backend, IAM V3 environments must resynchronize templates in `0003 → 0004 → 0005` order, and IAM V4 environments must resynchronize Action and Role models. Verify that existing users have `system_access` and grant it where required. Model synchronization alone does not automatically backfill permissions for all existing users; without the required permission, users may lose access to basic APIs after upgrading.
- KMS deployments using initial package import must upgrade the chart together with a File image containing the new adminclient command. The Job requires access to the global envelope and the private key supplied through `BK_NODEMGR_KMS_PRIVATE_KEY_GLOBAL`. Non-KMS deployments retain their existing plaintext configuration path. KMS-issued tokens have a fixed 24-hour lifetime, and `--expire-hours` has no effect in this mode.
- Before using custom legacy V2 directories, configure the deployment entry for the target operating system and arrange any migration of already-deployed plugins separately. Directory configuration alone does not enable compatibility installation.
- Building the services from source requires Go `1.26.10`.

**Known issues**

- Refreshing an out-of-band operation-history detail page directly may display `--` for the operator, operation time, and node role. Return to the history list and reopen the detail page.
