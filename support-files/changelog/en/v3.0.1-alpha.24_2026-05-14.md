## [Version: v3.0.1-alpha.24] - 2026-05-14

Full Changelog: [v3.0.1-alpha.23...v3.0.1-alpha.24](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.23...v3.0.1-alpha.24)

**Release Scope**

- Agent: The upgrade flow now auto-selects the default version when the request does not explicitly specify one, and improves both first-screen list loading and upgrade parameter delivery.
- Proxy: The upgrade request now carries the target version per host, and the pre-ordered plugin install flow now transfers the required release package and installer assets more completely.
- Plugin: Improved parameter configuration and process operation interactions, with stronger multi-namespace process handling and stop-process logic.
- Package: No standalone release package format change is introduced in this release. Default version selection and pre-ordered plugin installation still rely on existing package metadata.
- Backend/Control Plane: Improved host sync fault tolerance, workflow tracing and retry handling, and policy configuration viewing stability.
- Installer/Deployment: Relay `--version` output now returns a plain version string that is easier for scripts and release pipelines to consume.

**New Features**

- Agent upgrades can now auto-select the system default version when no target version is explicitly provided, making standard platform-based upgrades easier to launch.
- Proxy upgrades now support carrying the target version per host, which fits mixed-platform batch upgrades and cross-page host selection scenarios.
- The Proxy pre-ordered plugin install flow now transfers release packages, installer assets, and offline main config files together, reducing plugin installation failures after proxy rollout.
- The Plugin process handling flow now supports a multi-namespace proc handler, extending process trusteeship and control to multi-namespace scenarios.

**Optimizations**

- Optimized the Plugin parameter configuration pages around version selection, SchemaForm initialization, and settings panel display, reducing noisy warnings and improving parameter card readability.
- Agent node lists now load filter metadata asynchronously, shortening the first-screen wait time.
- Improved workflow execution stability by strengthening tracing and retry handling in background actions.
- Adjusted Relay version output to a plain version string so release checks and automation scripts can read it more directly.

**Bug Fixes**

- Updated the Plugin stop-process logic to account for host status, reducing ineffective stop operations on abnormal hosts.
- Fixed the policy configuration item pages so the add entry and read-only viewing interactions no longer expose editable actions in view mode.
- Updated `sync_host` to tolerate occasional duplicate host data and continue syncing, reducing the risk of full sync failures.
- Fixed installation table styling and validation cell rendering issues to improve readability on installation pages.
- Fixed Proxy upgrade request version delivery so mixed-platform host upgrades no longer suffer from target version mapping drift.

**Agent / Plugin / Package compatibility**

- The Agent and Proxy upgrade enhancements depend on updated upgrade APIs, protocol fields, swagger, and API Gateway resources staying aligned. API consumers need to pass the target version in the latest per-host request structure, or allow the system to fill the default version.
- The Proxy pre-ordered plugin installation enhancements depend on release packages, installer assets, and offline config files being available together. Offline or indirect install scenarios should upgrade the matching Backend and Frontend versions together.
- Plugin multi-namespace process handling depends on existing GSE trusteeship data being returned by namespace. Grey rollout environments should verify current process definitions and trusteeship results first.

**Component Dependencies and Upgrade Prerequisites**

- Default version auto-selection depends on complete release metadata for the target platform, so confirm that the required OS and CPU Arch already have a published default version before upgrading.
- The per-host Proxy target-version request format requires the Frontend, Backend, and proto definitions to stay aligned, so older callers should not keep sending the previous shared field structure.
- The Plugin parameter configuration improvements span version selection, parameter forms, and process operation pages, so deploying the updated frontend assets together is recommended for the full interaction set.
