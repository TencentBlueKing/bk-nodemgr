# BlueKing Node Manager v3.0.1

BlueKing Node Manager v3.0.1 brings together node connectivity across complex networks, centralized configuration, and plugin management. It covers Agent installation, network topology management, and plugin operation. Network Units organize connectivity paths, while configuration policies centrally manage node and plugin configurations, providing a consistent way to manage nodes across networks and businesses.

## Flexible cross-network management

Organize node connectivity with Network Areas, Network Units, and Access Points. Direct connectivity and multiple levels of Proxy bridging accommodate deployments across networks and isolated areas.

- Divide a Network Area into directly connected and non-directly connected Network Units according to actual network conditions.
- Configure upstream connections through Access Points and organize control, file, and data channels separately.
- Use the topology view to inspect management relationships and connection latency when investigating network issues.

The management topology describes connectivity relationships; the corresponding network reachability must still be available. Installing non-directly connected nodes also requires a Proxy with installation capabilities.

## Manage the full node lifecycle

Manage installation, upgrades, configuration reloads, restarts, and uninstallation for Agents and Proxies. Task records track the operation and its results.

- Use automatic installation or run installation commands manually. Proxies also support offline installation to establish the first connectivity node in an isolated network.
- Install Windows Agents through SSH or WMI to accommodate different host access conditions.
- Enter IPv4 and IPv6 addresses in batches on the new installation page and prepare installation information with Excel templates.
- Maintain out-of-band management information in batches or import it from Excel, with parsing results returned per row.

Preview installation parameters before execution, then inspect step logs and failure details to confirm results and investigate issues. After importing out-of-band management information from Excel, submit it on the page to save it.

## Centralized node and plugin configuration

Use configuration policies to manage Agent, Proxy, and plugin configurations centrally, reducing repetitive per-node configuration maintenance.

- Match configurations by scope to accommodate different node and business requirements.
- Adjust policy priorities and preview configuration results.
- Centrally manage parameters such as CPU, memory, script concurrency, data compression, and file tasks for Agents and Proxies.

A configuration preview does not execute changes.

## Unified plugin package and configuration delivery

Manage plugin resource packages, configuration templates, and runtime instances on hosts separately to support resource reuse and differentiated deployments.

- Manage versions of Agent, Proxy, plugin, certificate, and tool packages, with import and export for plugins and plugin packages.
- Use multiple main configuration and sub-configuration templates with custom rendering contexts to generate target configurations.
- Use V3 plugins while retaining compatibility management for legacy V2 plugins.
- Declare installation CPU and disk IO limits in plugin packages to control resource usage during installation and upgrade extraction.

V2 compatibility deployments require the corresponding legacy plugin packages; package formats are not converted automatically. Installation throttling does not replace resource management for running plugin processes.

## Collaboration through tenants and permissions

Support multi-business and multi-tenant collaboration, with tenant-isolated management data and artifacts and resource-scoped access control.

- Manage plugin enablement, artifact metadata, and file paths independently for each tenant.
- Synchronize shared artifacts from the `system` tenant to other tenants, combining centralized delivery with tenant-specific maintenance.
- Use management or read-only permissions for nodes, plugins, configuration policies, topology, and resource packages.
- Query task history and resource operation records within the calling user's authorized scope.

Enable and configure IAM V3 or IAM V4 according to the environment. Upgrading services does not automatically switch permission systems or migrate existing authorizations.

## Open integration and AI-assisted queries

Integrate with automation platforms through open APIs and use MCP queries constrained by user permissions.

- Query business topology, Network Areas, Network Units, Access Points, hosts, and other topology objects.
- Inspect node and plugin workflows, execution instances, and step logs for execution diagnostics.
- Let AI assistants retrieve topology and task information through MCP to understand the environment and investigate execution issues.

Configure and enable MCP capabilities in the gateway. Queries remain subject to user identity and resource permissions; these topology and execution diagnostic queries do not provide modification, retry, or termination operations.
