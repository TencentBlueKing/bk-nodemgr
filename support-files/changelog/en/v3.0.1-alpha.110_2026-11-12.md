## [Version: v3.0.1-alpha.110] - 2026-11-12

Full Changelog: [v3.0.1-alpha.109...v3.0.1-alpha.110](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.109...v3.0.1-alpha.110)

> Important notes

- Explicit IAM V3 Action resource binding replacement now deletes and recreates the Action instead of updating it in place. The existing `--allow-action-replace` flag remains disabled by default. Policy deletion is irreversible, existing grants are not converted automatically, and the Action is temporarily unavailable between deletion and recreation. The flow has no transaction or automatic rollback. Verify the system, tenant, and affected users/groups before execution, then reconfigure and verify permissions for the new resource dimension.
- References from action groups, common actions, and resource creator actions may block Action deletion; the tool does not automatically clean up these configurations. After recreation, synchronize and check the related configurations in `0003`–`0005`; do not rely on in-place updates to preserve references.

**Release scope**

- Backend/Control Plane: Fixes Action binding replacement in the IAM V3 model migration tool and concurrent crashes during multi-platform package generation and publication in the File service, and aligns release phase recognition in version logs.
- Frontend: Path validation and error navigation for custom deployment configurations in Network Units.
- Installer/Deployment: Upgrade and recovery guidance for IAM V3 model synchronization.

**Improvements**

- Version logs recognize the `alpha`, `beta`, and `release` phases in the project version format and support versions with an optional mark. The `rc` phase is no longer accepted: existing `rc` changelog files are no longer listed, and detail queries no longer accept those versions.
- The Network Unit form validates custom deployment paths by operating system. Unix-like paths must start with `/` and contain no control characters. Windows accepts drive-absolute or UNC paths and rejects invalid characters and reserved names. On submission, the form navigates to the operating system and field with the invalid path. Windows IPC ports are not validated as filesystem paths.

**Bug fixes**

- Fixes File service termination with `fatal error: concurrent map writes` during multi-platform package generation or publication. This covers Agent, Proxy, Proxy generation from server packages, V3 plugins, legacy V2 plugins, and external plugin packages. No data migration is required.
- Fixes failed in-place updates when an IAM V3 Action's resource binding changes. With explicit replacement opt-in, the tool validates the target definition, submits policy cleanup, deletes the old Action, and recreates it only after confirming its absence. Recreation preserves existing writable fields omitted from the request. Unchanged bindings still use ordinary updates without deleting policies or the Action.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats, or API / Proto contracts.

**Component dependencies and upgrade prerequisites**

- IAM V3 policy cleanup requires IAM SaaS ≥ 1.4.15 and backend ≥ 1.7.7; migration stops if unsupported. The replacement flag applies to all binding-changing `upsert_action` operations in the selected file or directory and does not change explicit `update_action` behavior. Review all affected bindings before execution and use `-f` to narrow the scope when needed. `--dry-run` only lists files without querying models or validating dependencies or policy impact.
- Policy cleanup and Action deletion may be asynchronous; a successful API response does not mean completion. The tool submits cleanup and deletion requests only once and waits for the old Action to disappear before creating it. Deletion failures, query failures, or wait timeouts stop the flow without attempting creation or automatically resending deletion requests. Inspect remote state before retrying after a failure or an unknown outcome.
- After migrating the old `package_history_view` binding to `package_type`, reconfigure and verify permissions at the `package_type` dimension. For recovery when the Action has been deleted, already has the target binding, or still has the old binding, see the [IAM V3 migration guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.110/support-files/bkiamv3/README.md#显式替换-action-资源绑定).
