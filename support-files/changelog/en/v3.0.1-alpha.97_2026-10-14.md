## [Version: v3.0.1-alpha.97] - 2026-10-14

Full Changelog: [v3.0.1-alpha.96...v3.0.1-alpha.97](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.96...v3.0.1-alpha.97)

**Release scope**

- Backend/Control Plane: Added read-only deploy policy preview and ordered config policy preview support.
- Frontend: Added and improved config policy sort previews and related strategy management workflows.
- Operations/Deployment: Updated post-upload Package permission grants and unified ServiceAccount configuration for Helm workloads.

**New features**

- Added the read-only `POST /api/v3/deploy_policy/preview` API to preview the calculated state of an enabled deploy policy without executing changes.
- Added an option to control config policy preview precedence with an ordered list of enabled policy IDs.
- Added configuration for the unassigned network-area ID, with a default value of `-1`.

**Improvements**

- Improved Agent and Plugin config policy sorting and preview behavior.
- Improved deploy policy calculation and target-state preview.
- In IAM V4 mode, grant the uploader management permission for the corresponding Package after a successful Package upload.
- Set `serviceAccountName` consistently for Helm services and sync Jobs, with support for configuring the ServiceAccount name and annotations through `serviceAccount`.

**Bug fixes**

- Fixed config policy preview and list error handling.
- Fixed compatibility mode propagation for pre-ordered plugins.
- Fixed configuration policy event details for priority reorder operations.
- Fixed the install button remaining enabled after Agent and Proxy installation preview data was cleared.

**Agent / Plugin / Package compatibility**

- This version does not change Agent, Plugin, or Package formats.

**Component dependencies and upgrade prerequisites**

- The Helm chart changes the default `serviceAccount.create` value from `true` to `false`; when `serviceAccount.name` is not set, workloads use Kubernetes's `default` ServiceAccount. Environments that require a dedicated ServiceAccount must set `serviceAccount.create: true` or configure an existing `serviceAccount.name` during upgrade, and retain the required permissions.
- A failure to grant the post-upload Package management permission does not roll back an upload that has already completed; IAM V4 deployments should ensure that the corresponding role-grant capability is available.
