## [Version: v3.0.1-alpha.100] - 2026-10-20

Full Changelog: [v3.0.1-alpha.99...v3.0.1-alpha.100](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.99...v3.0.1-alpha.100)

**Release scope**

- Backend/Control Plane: Plugin install and other V1 plugin operation workflows support concurrency throttling through dedicated Global Settings; KMS TLS configuration loading and validation are adjusted.
- File Service: Package structure is validated before import and release; V3 plugin `project.yaml` supports `installCpuLimit`.
- Installer: Adds the `--cpu-limit` parameter and trace correlation.
- Deployment: Helm init containers check storage with `bk-nodemgr-adminclient database check`; adminclient gains a `database` subcommand.
- Relay Plugin: Exposes APM tracing configuration.
- Frontend: Improves permission application, menu permission checks, and task history time filtering.

**New features**

- V3 plugin `project.yaml` supports `installCpuLimit`, which controls the CPU ratio the installer uses when processing tgz packages during plugin install/upgrade. Backend injects `--cpu-limit` into the generated install/upgrade script only when `0 < installCpuLimit < 1`. Behavior is unchanged when it is unset, `0`, or `1`; V2 plugin packages ignore the field.
- The installer adds the global parameter `--cpu-limit` to limit CPU usage while compressing and decompressing Agent/Plugin tgz packages, reducing the risk of saturating single-core hosts or cgroup-limited containers. It does not limit disk IO and does not cover the `pluginv2` subcommand.
- The installer generates a root trace at startup, prints the `trace-id`, and injects the W3C `traceparent` header into outbound HTTP requests, so installer activity can be correlated with server logs and APM. The installer does not export spans.
- Adds the Global Setting `oper_plugin_install_max_concurrency_num` (default `200`). Each plugin install workflow limits its own concurrency to this value; no limit is shared across workflows. The throttle applies to the v1 plugin install path only.
- V1 plugin upgrade, uninstall, apply/remove sub config, start/restart/stop process, migrate from v2, and start debug operations now use ordered triggers, each with an `oper_plugin_<operation>_max_concurrency_num` setting (default `200`) for its workflow concurrency limit. The limit is fixed when a workflow is created; changing a setting affects only subsequent workflows. Plugin V2, node, and package import operations are outside this change.
- adminclient adds a `database` subcommand that checks and connects to etcd, Redis, and MongoDB, and adminclient configuration can now be loaded from KMS. The ops scripts `script_tools/ops/{etcd,mongo,redis}.sh` now connect through this subcommand.
- The relay plugin configuration adds APM tracing options: exporter type, OTLP endpoint, protocol, insecure, headers, service name, and trace sample rate. Behavior is unchanged when they are not configured.

**Improvements**

- File Service validates package structure before importing and releasing Agent, Server, Plugin, bintool, plugin_bintool, and certificate packages. It rejects empty packages, missing required files, unknown platforms, and packages with incomplete content for a provided platform. Certificate packages require eight non-empty files at the root or under `cert/`. plugin_bintool publishes only the generations actually provided.
- In Helm deployments, the storage init containers of backend, application, and file now check etcd and MongoDB with `bk-nodemgr-adminclient database check` and retry until storage is ready, avoiding `Init:CrashLoopBackOff` when storage starts slowly during first install.
- Adjusts TLS file loading: TLS configurations that are not enabled are no longer converted or validated.
- Frontend improvements: resource instance descriptions when applying for control-unit permissions, business-related permission checks for the left menu, control-unit permission application in the topology graph, and time filtering in task history.
- The frontend and image Dockerfiles declare `# syntax=docker/dockerfile:1`, avoiding build failures caused by different default parsers across build environments.

**Agent / Plugin / Package compatibility**

- This version does not change Agent, Plugin, or Package formats; `installCpuLimit` is an optional field in V3 plugin `project.yaml`.
- Package structure validation may reject packages that were previously importable but are structurally incomplete. Confirm package contents are complete before importing.
- This version does not change API Gateway resource definitions.

**Component dependencies and upgrade prerequisites**

- Helm init containers depend on `bk-nodemgr-adminclient` in the module images; upgrade the module images and the chart together.
- `--cpu-limit` requires the installer from this version; earlier installers do not recognize the parameter.
