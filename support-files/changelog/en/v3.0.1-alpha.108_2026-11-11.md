## [Version: v3.0.1-alpha.108] - 2026-11-11

Full Changelog: [v3.0.1-alpha.107...v3.0.1-alpha.108](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.107...v3.0.1-alpha.108)

> Important notes

- Automatic IAM V4 Action binding replacement requires explicit opt-in. It deletes and recreates the Action without cascading dependency cleanup. Synchronization stops if IAM refuses deletion because of role, authorization, or other dependencies, without expanding the cascade scope. Existing grants are not migrated automatically, and failures do not automatically roll back IAM model changes already written.

**Release scope**

- Backend/Control Plane: The IAM V4 model migration tool adds optional automatic Action binding replacement.
- Installer/Deployment: The Helm IAM V4 synchronization Job adds a replacement switch; API Gateway synchronization troubleshooting documentation clarifies tenant warnings.

**New features**

- The IAM V4 migration tool adds `--allow-action-replace`, disabled by default. When enabled, `upsert_action` with a conflicting resource binding reuses the default non-cascading delete-and-recreate flow of `replace_action`. Binding changes are still rejected without this flag.
- Helm adds `iamV4.option.allowActionReplace`, defaulting to `false`. Setting it to `true` passes `--allow-action-replace` to the IAM V4 synchronization Job.

**Improvements**

- Clarifies repeated tenant warnings during API Gateway synchronization: the warning alone does not indicate an incorrect tenant or a failed synchronization. If the tenant is correct and synchronization succeeds, no configuration change or Job rerun is needed. This is a troubleshooting documentation update only; SDK warning behavior is unchanged.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.

**Component dependencies and upgrade prerequisites**

- Upgrade the Chart and Backend image together to use the Helm replacement switch. The migration tool ships in the Backend image; older tools do not support the new flag.
- Before enabling replacement, verify the target system, tenant, affected roles, and grants. Synchronize roles and verify grants after replacement. `--dry-run` only queries models and prints the plan without calling the deletion API; it cannot prove that IAM server-side dependencies permit deletion.
- For procedures and recovery limitations, see the [IAM V4 model migration guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.108/support-files/bkiamv4/README.md#显式替换-action-绑定).
