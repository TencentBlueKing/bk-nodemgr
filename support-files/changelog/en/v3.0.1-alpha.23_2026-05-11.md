## [Version: v3.0.1-alpha.23] - 2026-05-11

Full Changelog: [v3.0.1-alpha.22...v3.0.1-alpha.23](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.22...v3.0.1-alpha.23)

**Release Scope**

- Agent: Added the install compatibility mode parameter, improved install preview and strategy display, and fixed the network area name overflow issue.
- Proxy: Added installation through Excel template import, and improved the close confirmation behavior on install and reinstall pages.
- Plugin: Added compatibility mode support for installation, plugin process stop and restart operations, and the frontend reinstall entry.
- Package: Added multi-platform queries for release plugin config variables.
- Backend/Control Plane: Improved install API parameter consistency, plugin process synchronization, announcement scheduling, order trigger handling, and host login user fallback.
- Installer/Deployment: No standalone installer packaging change in this release. Compatibility enhancements take effect through the existing install and release flow.

**New Features**

- Added the compatibility mode parameter to NodeAgent, NodeProxy, and Plugin install APIs for compatibility-oriented installation flows.
- Added the plugin config overwrite action to the Plugin install flow for compatibility mode configuration override.
- Added Proxy installation through Excel template import to support batch onboarding from import templates.
- Added Plugin process stop and restart APIs so operators can control plugin processes on specified hosts.
- Added the Plugin frontend reinstall entry, allowing selected existing plugin processes to carry host and version data into the reinstall flow. 
- Added multi-platform queries for release plugin config variables so platform-specific configuration can be retrieved before rollout.

**Optimizations**

- Optimized the Plugin backend process synchronization workflow to reduce failures in the process status sync path.
- Improved the Plugin installation configuration page so config variable forms render more reliably.
- Optimized the Plugin frontend flows for install, reinstall, upgrade, stop, and restart, including version and config prefill based on selected host platforms. 
- Improved Plugin frontend confirmation dialogs for batch uninstall, stop, and restart by showing the target processes and reducing accidental operation risk. 
- Optimized Agent strategy sorting and preview interactions to improve strategy readability.
- Added damaged-node color differentiation in Agent node displays to make abnormal states easier to identify.
- Added indexes to the Host Mongo table to improve related query performance.

**Bug Fixes**

- Fixed inconsistent IP list parameters between install-check and install APIs so install preview stays aligned with the actual install request.
- Fixed the close confirmation behavior on Proxy install and reinstall pages to reduce accidental state loss.
- Fixed the global business selector so selected businesses are displayed correctly after page refresh. 
- Fixed inconsistent Agent/Proxy view permission filtering in the plugin process list so unauthorized nodes do not enter plugin operation scope. 
- Fixed announcement scheduling so announcement requests are triggered by the configured period.
- Fixed the order trigger handler logic in the job trigger flow.
- Fixed host login user fallback in the host information flow.
- Fixed source tracing instance ID loading so it uses the configured value.
- Fixed network area name overflow in list displays.

**Agent / Plugin / Package compatibility**

- The compatibility mode enhancements cover NodeAgent, NodeProxy, and Plugin installation flows. API consumers need to align with the newly added parameters after upgrade.
- The Plugin frontend reinstall, stop, and restart flows depend on the backend Plugin operation APIs. Ensure PR #2272 is merged and this branch is rebased before delivering the final release notes.
- Release plugin config variable queries now return multi-platform results. Multi-platform rollout scenarios should re-check delivered configuration per target platform.

**Component Dependencies and Upgrade Prerequisites**

- Proxy installation through Excel template import depends on the existing template import flow and updated install APIs, so the Frontend and Backend versions should be upgraded together.
- Plugin process stop and restart operations, together with compatibility mode parameters, depend on synchronized API and protocol upgrades to avoid version mismatches between callers and services.
- These release notes already include pending PR #2272. Before creating the final release PR, rebase after that PR is merged and re-check that the changelog matches the actual compare range.
