## [Version: v3.0.1-alpha.112] - 2026-11-16

Full Changelog: [v3.0.1-alpha.111...v3.0.1-alpha.112](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.111...v3.0.1-alpha.112)

**Release scope**

- Backend/Control Plane: Install-without-start for V3 plugins, batch stop of legacy V2 plugin processes, and a plugin sub-config delivery fix.
- File service: On-demand cleanup APIs for expired package files without bindings.
- Frontend: Fallback handling in the permission dialog when the apply URL is empty.
- Deployment: New product user Wiki link configuration; SSH connection failure logs now include a troubleshooting guide link.

**New features**

- Adds an install-without-start API for V3 plugins: delivers and installs plugin packages in batch and renders configurations without starting the plugin process. If the process is running on a target host, it is stopped first and remains stopped after the task completes. The API returns a `workflow_id`; check workflow records for execution results.
- Adds a batch stop API for legacy V2 plugin processes, selected by host and plugin name. The API returns a `workflow_id`; check workflow records for execution results.
- The File service adds on-demand cleanup APIs for expired upload files, package release files, and export files of the current tenant, reclaiming storage without bindings.
- SSH connection failure logs now include a localized troubleshooting guide link. The new `backend.wiki` configuration selects the product user Wiki source; GitHub mode is currently supported and defaults to the official repository.

**Bug fixes**

- Fixes plugin sub-configs not being redelivered when the custom configuration rendering context changes. Context content changes now also trigger re-rendering and delivery of the affected host sub-configs, instead of only filling in missing ones.
- Fixes the permission dialog offering no navigation entry when `apply_url` is empty; it now falls back to the IAM home page.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- Adds two plugin operation APIs and three File service cleanup APIs without changing existing API paths or request/response structures.

**Component dependencies and upgrade prerequisites**

- Environments using API Gateway must synchronize this release's resources before calling the new plugin APIs. Both new plugin APIs are asynchronous; a successful API response does not mean the plugin is installed or the process is stopped. Confirm results through workflow records.
- The `backend.wiki` configuration has defaults, so existing deployments can upgrade without extra configuration. Adjust it in Helm values to point to a private documentation repository if needed.
