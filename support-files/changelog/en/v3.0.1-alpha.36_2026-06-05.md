## [Version: v3.0.1-alpha.36] - 2026-06-05

Full Changelog: [v3.0.1-alpha.35...v3.0.1-alpha.36](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.35...v3.0.1-alpha.36)

> Important notice
- REST services now bind IPv4 and IPv6 explicitly according to configuration. For dual-stack deployments, configure both `IP` and `IPV6`; do not rely on implicit dual-stack behavior from a single listen address.

**Release scope**

- Agent: This release does not change Agent runtime behavior.
- Plugin: This release does not change Plugin configuration or runtime behavior.
- Package: This release does not change Agent / Plugin / Package formats.
- Backend/Control Plane: Fixes shared REST server listen behavior in IPv4/IPv6 dual-stack environments, preventing services from implicitly binding to an unintended network protocol.
- API / Gateway: This release does not change external API contracts, Swagger files, or API Gateway resource definitions.
- Frontend: This release does not change frontend pages.
- Installer/Deployment: This release does not change deployment parameters.

**Bug fixes**

- Fixed Backend/Control Plane HTTP service startup so Go's default `tcp` listen no longer creates implicit dual-stack binds. IPv4 and IPv6 now use `tcp4` and `tcp6` listeners separately.
- Fixed the risk of inconsistent HTTP and HTTPS listen behavior or implicit port ownership in dual-stack configurations, reducing startup failures and unintended exposed addresses.

**Agent / Plugin / Package compatibility**

- Agent, Plugin, and Package formats remain compatible.
- REST service listen behavior is stricter: deployments that need dual-stack access should configure both IPv4 and IPv6 listen addresses; a single configured address listens only on its own protocol family.

**Component dependencies and upgrade prerequisites**

- This release does not introduce new external component dependencies.
- Before upgrading, verify that Backend/Control Plane service `IP` / `IPV6` configuration matches the expected exposed protocol families, and validate service startup in dual-stack environments.
