## [Version: v3.0.1-alpha.109] - 2026-11-11

Full Changelog: [v3.0.1-alpha.108...v3.0.1-alpha.109](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.108...v3.0.1-alpha.109)

> Important notes

- IAM V3 and V4 replace Action bindings differently: V3 deletes the Action's policies and updates the Action in place without deleting it; V4 deletes and recreates the Action. Both require explicit opt-in, do not migrate existing grants, and do not automatically roll back failures. Verify the target system, tenant, and authorization impact before execution, then reconfigure and verify permissions for the new resource dimension.
- IAM V4 automatic replacement now removes the old Action from roles. Subsequent role synchronization restores only members declared in templates; custom role members absent from templates require separate restoration. RBAC/ABAC authorizations are not automatically cleaned up, and other dependency conflicts still block replacement.

**Release scope**

- Backend/Control Plane: Explicit IAM V3 model binding replacement, role membership cleanup during IAM V4 automatic replacement, and platform filtering of published plugin packages.
- Installer/Deployment: IAM model synchronization upgrade and recovery guidance, and API Gateway MCP synchronization troubleshooting for stage overrides.

**New features**

- The IAM V3 migration tool adds `--allow-action-replace`, disabled by default. `upsert_action` stops on resource binding changes unless explicitly enabled; with the flag, it validates the target definition, deletes policies, and updates the Action in place, preserving references such as action groups and common actions. Unchanged bindings do not trigger policy deletion. The flag applies to all binding-changing `upsert_action` operations in the selected file or directory and does not change explicit `update_action` behavior.

**Improvements**

- Adds troubleshooting for `mcp_servers: 该字段是必填项` (required field) when MCP synchronization is enabled: overriding `apigwSync.config.stages` replaces the entire default list, so every stage needs a nonempty `mcp_servers` configuration. This is documentation only; synchronization behavior is unchanged. Rerunning the synchronization Job synchronizes resources and may publish a version; it is not read-only validation.

**Bug fixes**

- Fixes role member references blocking Action deletion during IAM V4 automatic replacement. With the existing `--allow-action-replace` flag or Helm `iamV4.option.allowActionReplace` enabled, replacement uses `cascade: ["role"]` to remove members before deleting and recreating the Action. Opt-in remains disabled by default; explicit `replace_action` without `cascade` remains non-cascading.
- Fixes validation failures when packages for other platforms have already been published under the same plugin name and version. Published results are filtered by the platforms in the current upload, covering V3 plugins, legacy V2 plugins, and external plugin packages.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats. Published plugin packages must still match the platform set of the current upload.

**Component dependencies and upgrade prerequisites**

- IAM V3 policy cleanup requires IAM SaaS ≥ 1.4.15 and backend ≥ 1.7.7; migration stops if unsupported. Policy deletion is irreversible. `--dry-run` only lists files without querying models or validating policy impact. If policy deletion succeeds but the update fails, inspect remote state before retrying.
- The IAM V3 base template now declares the final `package_type` binding for `package_history_view`; migrating an existing old binding requires explicit replacement opt-in. Render into an empty output directory to avoid stale JSON from the removed standalone rebinding template. See the [IAM V3 migration guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.109/support-files/bkiamv3/README.md#显式替换-action-资源绑定) for procedures and recovery limitations.
- IAM V4 automatic replacement requires a Backend tool image containing role cascade cleanup. `--dry-run` only queries models and prints the plan without calling the deletion API; it cannot prove that dependencies permit deletion. Synchronize roles and verify grants after replacement. See the [IAM V4 migration guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.109/support-files/bkiamv4/README.md#显式替换-action-绑定) for recovery procedures.
