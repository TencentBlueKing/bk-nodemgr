## [Version: v3.0.1-alpha.114] - 2026-11-18

Full Changelog: [v3.0.1-alpha.113...v3.0.1-alpha.114](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.113...v3.0.1-alpha.114)

> Important notes

- `bk_token` authentication now defaults to `/open/bk-tokens/userinfo/` instead of selecting the API automatically by tenant mode. Single-tenant deployments that still depend on `/accounts/get_user/` must set `application.config.bkSaaS.bkLogin.useLegacyAPI=true` when upgrading. This compatibility mode does not support multiple tenants. `bk_ticket` behavior is unchanged.

**Release scope**

- Backend/Control Plane: Paginated and compatibility queries for legacy V2 plugin processes, node and plugin execution diagnostics, and batch orchestration for plugin sub-config projection.
- Application/Frontend: Login API selection, configuration policy Network Unit selection, and dropdown search fixes.
- Installer/Deployment: Login compatibility configuration, an API Gateway execution diagnostics MCP service, and a script to search container-local logs by Trace ID.

**New features**

- Adds `POST /api/v3/process/list_v2` to query legacy V2 plugin processes with pagination, count-only mode, and exact or fuzzy filters, returning process state and configuration details. Queries are narrowed to the caller's business-level `plugin_view` permissions. Item queries return up to 500 records per page; count-only queries return empty `items`.
- Adds user-state node and plugin execution diagnostics APIs and an `execution` MCP service to query workflows, operations, execution instances, and step logs. Queries are scoped to the calling user's permissions; retry, termination, and modification operations are not exposed.
- Adds `/bk-nodemgr/script/ops/trace.sh <traceid>` to search the current container's local logs by Trace ID and output file names, line numbers, and original log entries without a log exporter.

**Improvements**

- Legacy V2 plugin process compatibility queries and state synchronization now read host or process records in batches. Compatibility queries retain their existing response structure.
- V3 plugin sub-config projection can prepare multiple source plugins as a batch on one execution host and apply target configs in input order. Independent batches are not guaranteed to run serially.

**Bug fixes**

- Fixes Network Unit selection being cleared after switching Network Areas in Agent and plugin configuration policies. Switching now defaults to "Unlimited", and submission validates empty values to prevent an empty string from being submitted as a Network Unit ID.
- Fixes dropdown matching for businesses, Network Areas, and Network Units, supporting searches by name or partial ID. Editing an Agent configuration policy now preserves the "Unlimited" Network Unit value.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- `POST /api/v3/process/list_v2` reads only legacy V2 plugin process records and does not replace the current V3 plugin process query API. Existing API paths remain unchanged. Node and plugin workflow queries add deploy-policy filters and associated policy fields.

**Component dependencies and upgrade prerequisites**

- To use the default `bk_token` login API, configure accessible `endpoints`, `appCode`, and `appSecret` under `application.config.bkSaaS.bkLogin`, plus `user` for `authMode=un` or `accessToken` for `authMode=at`. `loginURL` is only for browser redirects and cannot replace the API gateway address. See Important notes for the legacy single-tenant compatibility switch.
- Before calling the new query APIs through API Gateway, synchronize and publish the corresponding gateway resources. Upgrading Backend alone does not expose these gateway APIs. Legacy V2 process queries require `plugin_view` permission for the target businesses. Execution diagnostics additionally require gateway application and user authentication, resource access permission, `system_access`, and the applicable Agent, Proxy, or plugin history-view permissions. The `execution` MCP service is disabled by default and must be enabled in the gateway before use.
- The Trace log script ships with this release's images and accepts only 32 lowercase hexadecimal characters as the Trace ID. It searches only persisted logs carrying that Trace ID under `/bk-nodemgr/log` in the current container, not across Pods. Run it separately in the relevant containers when investigating a multi-Pod request path.
