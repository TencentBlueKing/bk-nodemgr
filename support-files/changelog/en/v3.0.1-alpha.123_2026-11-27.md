## [Version: v3.0.1-alpha.123] - 2026-11-27

Full Changelog: [v3.0.1-alpha.122...v3.0.1-alpha.123](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.122...v3.0.1-alpha.123)

> Important notes

- Configuration policy APIs no longer accept or return the internal ordering value `priority`. Upgrade Application and Backend in the same maintenance window and pause configuration policy editing during the transition: editing through the new Application against an older Backend writes the ordering value as `0`. Roll back both components together as well.
- The documentation center address now consists of a URL prefix and a Node Manager documentation path. Environments configured with a complete documentation URL must split it into these two settings to avoid duplicated paths.

**Release scope**

- Backend/Control Plane: historical plugin installation parameter queries, configuration policy ordering, and API field changes.
- Application/Frontend: read-only global variable queries, scheduled task execution details, and configuration policy ordering display.
- Installer/Deployment: separate documentation center settings, an IAM platform manager role, and a permission request shortcut.

**New features**

- The global variables page supports exact-name searches, pagination, refresh, and viewing and copying complete raw values. Variables are shared across tenants and include custom entries. The read-only page shows database values without supplying defaults or representing effective process configuration. Custom values may contain sensitive information; grant access only as needed.
- New historical plugin installation parameter APIs retrieve the host, plugin version, custom configuration, and deployment specification from selected installation operations for use in a new installation. Only `install_plugin` workflows are supported. Queries do not install, retry, or modify historical tasks, and automatic form population is not included.
- Added the IAM V4 `platform_manager` role and the IAM V3 Platform Manager permission request shortcut. Both contain only `system_access` and `platform_manage`; platform resource scope depends on actual grants. Neither automatically grants user permissions or access to all platform resources.

**Improvements**

- Scheduled task execution details now have a dedicated page with instance switching, per-step status and duration, execution logs, and manual refresh. Returning reopens the execution history of the corresponding workflow. The page remains read-only.

**Bug fixes**

- Ordinary configuration policy edits preserve the existing order. Backend-provided list ranks correct pagination display, and plugin configuration policy ordering previews load all enabled policies in the current business rather than only the current list page.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats. Host-side Agent or plugin upgrades are not required for these control plane and UI updates.
- Historical plugin installation parameters come from retained deployment records, not a complete snapshot of the original request. Missing records and fields are explicitly reported. Before reinstalling, complete missing parameters and confirm that the host, plugin version, and configuration are still valid.

**Component dependencies and upgrade prerequisites**

- Update Application, Frontend, and Backend together. Configuration policy callers must remove dependencies on `priority` and use `priority_rank` for list display. This rank starts at `1` within the filtered results and is omitted for disabled policies and detail responses. Explicit reordering and previews continue to use ordered policy IDs. No database migration is required.
- Global variable queries require `system_access` and `platform_manage` on `platform_resource/global_settings`. Scheduled task details retain the `platform_manage` requirement on `platform_resource/scheduler_workflow`. Historical plugin installation parameter queries require system access plus plugin history viewing and plugin viewing permissions for every business covered by the historical workflow.
- Before using the new platform manager authorization entries, synchronize the corresponding IAM models and grant users the appropriate resource scope. For IAM V3, register `platform_manage` from `0006` before synchronizing the updated `0005` common action shortcuts. For IAM V4, synchronize the updated `0004` role template. When rolling back an environment where the role has been synchronized, rerunning the old V4 template does not delete the new role; revoke its grants before deleting it.
- Application setting `front.bkDocsCenterURL` now specifies the documentation center URL prefix. The new `front.bkDocsCenterNodemgrDocPath` specifies the documentation path and defaults to `/markdown/NodeMgr/UserGuide/Introduce/Overview.md`. An empty prefix keeps the documentation link empty. Helm and Helmfile use the same fields under `application.config.front`; Docker Compose adds the `BK_NODEMGR_APPLICATION_DOCS_CENTER_NODEMGR_DOC_PATH` environment variable.
