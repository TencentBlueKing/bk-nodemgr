## [Version: v3.0.1-alpha.90] - 2026-09-20

Full Changelog: [v3.0.1-alpha.89...v3.0.1-alpha.90](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.89...v3.0.1-alpha.90)

**Release scope**

- Backend/API: sync API trigger ID responses, plugin process status persistence, and stale process status correction.
- Installer/Deployment: Helm Loki log collection and Kubernetes-version-aware traffic policy handling.
- Documentation/Operations: tracing OTLP protocol configuration, third-party APIGateway permissions, APM debug workflow, and Helm monitoring/log collection guidance.

**New features**

- Sync APIs now return the one-time workflow trigger ID.
- Added process status storage operations for plugin process observation.
- Added Sync APIs for correcting stale plugin process statuses to `unknown`.
- Added Helm Loki log collection support.

**Improvements**

- Documented tracing OTLP protocol configuration.
- Updated third-party APIGateway permission documentation.
- Added bk-nodemgr APM debug skill documentation.
- Documented Helm self-monitoring ingress and Loki log collection.

**Bug fixes**

- Recorded process observation timestamps.
- Resumed synchronization for managed unknown plugin processes.
- Initialized missing scheduled workflows.
- Fixed plugin remove sub config frontend type mapping so lists and details show the expected value.
- Guarded Helm internal traffic policy by Kubernetes version.

**Agent / Plugin / Package compatibility**

- Sync API response data now uses `trigger_id` for the returned workflow trigger ID.
- This version does not change Agent / Proxy, Plugin, or Package formats.

**Component dependencies and upgrade prerequisites**

- Loki log collection and tracing OTLP protocol configuration are optional and should be enabled only after confirming the related deployment values.
- Helm internal traffic policy handling now follows the Kubernetes version.
