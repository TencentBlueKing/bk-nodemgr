## [Version: v3.0.1-alpha.91] - 2026-09-23

Full Changelog: [v3.0.1-alpha.90...v3.0.1-alpha.91](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.90...v3.0.1-alpha.91)

> Important
> - If embedded Loki is enabled, review values and storage settings before upgrading its chart from `3.8.2` to `6.30.1`; do not assume existing configuration or data is compatible without verification.
> - Before deploying the Helmfile `example`, supply environment credentials, gateway URLs, and business settings, and check storage classes and monitoring resources. Self-monitoring remains disabled by default in the main Helm chart.

**Release scope**

- Backend/API: Orphan process cleanup workflow and tenant initialization, IAM v4 authorization handling, and HTTP status for third-party request failures.
- File/Package: BKRepo downloads and file stream handling.
- Installer/Deployment: Helmfile example deployment, optional Pyroscope profiling, and updated embedded Loki and self-monitoring wiring.

**New features**

- Added `POST /api/v3/sync/process/clean_orphan` to asynchronously remove stale orphan process records whose hosts no longer exist. The response includes a `trigger_id` to track the workflow.
- Admin tenant initialization now creates tenant storage and launches business/host, network area, default Plugin, and shared release sync workflows.
- Added a multi-release Helmfile example with environment-specific values rendering. Helm can optionally deploy Pyroscope and configure profiling for the application, backend, and file services.

**Improvements**

- Upgraded the embedded Loki chart to `6.30.1`; Grafana now provisions a Pyroscope data source and self-monitoring signal links.
- Streamed BKRepo downloads and validated gzip trailers to reduce memory use for large downloads and detect incomplete archives.
- Bounded scans of orphan process candidates to avoid loading large result sets at once.

**Bug fixes**

- Fixed embedded Loki log collection paths and Helmfile self-monitoring and gateway defaults.
- Preserved Plugin deployment `last_sync_at` and refreshed stale process sync timestamps.
- Fixed IAM v4 authorization for lower-level resources and prevented duplicate file stream closes.
- Changed third-party request failures from HTTP `500` to `422` to distinguish upstream request failures from internal errors.

**Agent / Plugin / Package compatibility**

- This version does not change Agent / Proxy, Plugin, or Package formats. The new Sync API does not replace existing endpoints. Clients relying on HTTP `500` for third-party request failures must handle `422`.

**Component dependencies and upgrade prerequisites**

- Pyroscope, Loki, Alloy, and other self-monitoring components remain disabled by default in the main Helm chart. Enabling embedded Pyroscope also enables profiling for services without an explicit `profiling.enabled` value. For an external Pyroscope, set both `profiling.enabled: true` and `profiling.serverAddress`; configure persistence to retain embedded profiles.
- The Helmfile `example` enables self-monitoring and deploys dependencies, services, and monitoring separately. Before upgrading an existing Helm installation, review releases, namespaces, storage, and custom values, especially Loki storage and schema settings.
