## [Version: v3.0.1-alpha.98] - 2026-10-16

Full Changelog: [v3.0.1-alpha.97...v3.0.1-alpha.98](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.97...v3.0.1-alpha.98)

**Release scope**

- Backend/Control Plane: Added shared plugin package imports, KMS-based credential decryption in service configuration, and a fix for failure results of pre-ordered plugin install actions.
- Frontend: Improved search value validation feedback on the Agent list and the user info panel position when the notice bar is shown.
- Operations/Deployment: Added External Secrets Operator (ESO) based KMS credential integration to the Helm chart.

**New features**

- Added the optional request parameter `is_shared` to the plugin package import APIs `/api/v3/package/workflow/import/v3/plugin`, `/api/v3/package/workflow/import/v2/plugin`, and `/api/v3/package/workflow/import/v2/external_plugin` to publish the imported package as a shared package. It takes effect only for `system` tenant requests and is ignored for other tenants.
- Services can decrypt KMS credential envelopes at startup and override the related credential configuration items.
- Added the `kms` Helm configuration. When enabled, ESO pulls KMS credentials for the global scope and the application, backend, and file modules; private keys are injected as environment variables and envelopes are mounted as files.

**Improvements**

- On the Agent list, input that matches no search condition is now removed with a warning, and `ip` or `area_ip` search values that are not in a valid IP format trigger a warning.
- The user info panel moves down together with the navigation when the notice bar is shown.

**Bug fixes**

- Fixed failure results of pre-ordered plugin install actions not being returned correctly.

**Agent / Plugin / Package compatibility**

- This version does not change Agent, Plugin, or Package formats.
- The new `is_shared` import parameter is optional; behavior is unchanged when it is omitted.

**Component dependencies and upgrade prerequisites**

- `kms.enabled` defaults to `false`. Enabling KMS credential integration requires External Secrets Operator in the cluster and `kms.server` plus the per-module `path`, `role`, and `credential` values that match the actual KMS registration.
