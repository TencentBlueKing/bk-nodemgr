## [Version: v3.0.1-alpha.27] - 2026-05-18

Full Changelog: [v3.0.1-alpha.26...v3.0.1-alpha.27](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.26...v3.0.1-alpha.27)

**Release Scope**

- Agent: No direct changes.
- Proxy: No direct changes.
- Plugin: Completed compatibility handling for legacy v2 plugin and standardized actions.
- Package: No standalone package format changes; Backend API / Gateway condition fields are synchronized.
- Backend/Control Plane: Added process v2 storage tables, optimized host statistics and process list query performance, expanded user info return, and improved username display in multi-tenant scenarios.
- API / Gateway: Synchronized the Process condition field from `node_generation` to `generation` and aligned it as an `int64` array.
- Installer/Deployment: Completed full install and uninstall commands for legacy v2 plugin, and adjusted application frontend configuration to docker and helm.

**New Features**

- Added process v2 storage tables in Backend to support the process management v2 compatibility path.

**Optimizations**

- Optimized Backend host statistics query to use group by aggregation, reducing query overhead.
- Optimized Backend process list query for better performance.
- Synchronized connection cycle time during Agent info sync in Backend, reducing sync gap and data latency.
- Improved username display logic in multi-tenant scenarios on Frontend for better user experience.
- Optimized username display in personal center on Frontend.
- Expanded Backend WebUserInfo API to return more user information, supporting frontend display requirements.
- Adjusted application frontend configuration to docker and helm config files for easier deployment management.

**Agent / Plugin / Package compatibility**

- This release improves compatibility for legacy v2 plugin, including related action standardization and full install/uninstall flows.
- Existing Plugin v1 functionality remains compatible; API / Gateway consumers using Process condition fields should use `generation` instead of `node_generation`, with the field typed as an `int64` array.

**Component Dependencies and Upgrade Prerequisites**

- No extra component dependencies or upgrade prerequisites.
