## [Version: v3.0.1-alpha.106] - 2026-11-06

Full Changelog: [v3.0.1-alpha.105...v3.0.1-alpha.106](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.105...v3.0.1-alpha.106)

> Important notes

- The default `authIdentity` of the File basic server changes from `none` to `rest-server`. Deployments using the default values, or custom values that do not override this setting, will enable rest-server authentication on the basic server after upgrading. To keep the previous behavior, explicitly set `authIdentity: none` in your custom values.

**Release scope**

- Backend/Control Plane: sudo-based installation on Unix, Windows firewall configuration across full installer commands, the plugin process V2 search API, dedicated persistence for plugin V2 processes and main configurations with scheduled alive-process synchronization, and the source-plugin/target sub-configuration composition workflow.
- Application/Frontend: sudo installation entry, operator filter and deleted-host display in configuration policies, per-user browser local storage, and permission dialog and verification fixes.
- Installer/Deployment: Extended effective timing of Windows firewall configuration, and the File basic server default authentication identity change.

**New features**

- The Agent/Proxy installation APIs and installation pages add an optional `is_sudo` parameter. Set it to true when the login user is non-root with passwordless sudo configured; installer commands then run with `sudo -n`. It defaults to false and only applies to Unix-like systems.
- Windows firewall configuration now applies to full installer commands (install, upgrade, reconfig, uninstall); it previously took effect only before installation. Only the Windows installer applies it, and ports are computed by the installer from the enabled features.
- Adds the plugin process search API `Process_ListV2ProcessesCompatible` (with API Gateway resources and Chinese/English documentation) for compatible listing of plugin V2 processes.
- Plugin V2 processes and main configurations are persisted in dedicated collections, plugin flows record process changes, and alive plugin process information is synchronized on a schedule.
- Adds the composition (compose) execution workflow for a source plugin and its target sub-configurations.
- Configuration policy lists support filtering by operator and display deleted hosts.
- Browser local storage (localStorage) is isolated per user, preventing data from leaking across users sharing the same browser.

**Bug fixes**

- Fixed permission verification errors incorrectly triggered by Agent/Proxy restart operations.
- Fixed the recurring permission dialog issue: permission recheck was missed when the multi-select business set changed, and stale permission details on the 403 page led to irrelevant apply dialogs; the topology module now loads business permission data as well.
- Fixed data normalization when reading process configuration custom context from MongoDB.
- Fixed network unit delete events not being snapshotted before asynchronous recording, which could leave incomplete records.
- Corrected the wording and display of Proxy installation tips.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- `is_sudo` is optional and defaults to false; existing installation requests behave as before.

**Component dependencies and upgrade prerequisites**

- Using `is_sudo` installation requires passwordless sudo to be configured for the login user on target hosts (`sudo -n` must succeed).
- Plugin V2 processes and main configurations use dedicated MongoDB collections enabled with the Backend upgrade; no historical data migration is involved.
