## [Version: v3.0.1-alpha.119] - 2026-11-25

Full Changelog: [v3.0.1-alpha.118...v3.0.1-alpha.119](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.118...v3.0.1-alpha.119)

> Important notes

- GSE Proxy network settings now support global configuration. Linux Proxy Bind IPs and ports prefer `gseDeployConfs[*].custom`, and the V1 File Agent, Topology Thrift, and File/Data Metric Exporter ports are added. Restart Backend after changes, and reconfigure existing Proxy nodes.
- The File service adds `file.config.userManager` to resolve the configured `gse.user`. BlueKing platform 7.3 requires user manager endpoints and application credentials in both `single` and `multiple` modes. For BlueKing platform 7.2 `single` mode, set `userManager.useLegacyUsername: true` in Backend, Application, and File together.
- A read-only Backend system configuration query is added. Callers require `platform_manage` on resource type `platform_resource` with resource ID `system_config`. Import and publish the corresponding API Gateway resources before calling it through API Gateway.

**Release scope**

- Backend/Control Plane: Global GSE Proxy network settings, hostid self-push, system configuration queries, plugin process expiry correction, File user resolution, plugin workflow filtering, and temporary file cleanup.
- Application/Frontend: Chinese and English Excel templates, table filter search, Network Area and Network Unit ID display, and history and plugin operation interaction fixes.
- Installer/Deployment: GSE Proxy and File user manager settings in Helm, Helmfile, and Docker Compose; Linux tools no longer use UPX compression.

**New features**

- Agent, Proxy, and Ops Excel templates support Chinese and English. The language follows the `blueking_language` cookie and defaults to Chinese.
- Adds read-only Backend system configuration queries through application-state `/api/v3/system_config/get` and user-state `/api/v3/open/system_config/get`. Responses contain a whitelisted view of tenant mode, IAM switches, and GSE installation defaults, without credentials, endpoints, or proxy addresses.
- GSE Proxy network settings can be configured globally to override the defaults in the Proxy release package env file. These settings apply only to Linux.
- Adds `gseDeployConfs[*].pluginCustom.hostIDPushMode: self`, which lets Node Manager generate and push the hostid file through GSE. The default remains `cmdb`.
- Table column filters support search, and Agent lists and Network Area/Unit tables display `[ID] name`.
- Plugin workflow operation lists support exact filtering by `bk_host_innerip` and `bk_host_innerip_v6`.

**Improvements**

- Expires stale running V3 and V2 plugin process states after a configurable number of alive-sync cycles. The new settings are `oper_correct_running_process_status_expiry_cycles` and `oper_correct_running_process_v2_status_expiry_cycles`, both defaulting to 3 cycles.
- File shared release synchronization now reconciles enabled and default-version state, preventing state drift after the source tenant changes.
- Plugin filesystem purge retries with exponential backoff on Unix and Windows. WMI installation and file temporary directories now clean up only the files and directories they own on both success and failure paths.
- Assigning a Proxy Network Unit now installs only `bk-nodemgr-relay`, without installing pre-ordered monitoring plugins.
- Linux tools disable UPX compression to avoid startup crashes on old kernels or in restricted environments.

**Bug fixes**

- Fixes stale IPv4/IPv6 either-or validation errors in Agent and Proxy installation forms.
- Fixes the node history DatePicker error caused by restoring timestamps instead of `Date` objects.
- Fixes selected tasks being lost when polling rebuilds the task detail table.
- Fixes plugin operation previews displaying an unassigned Network Unit as `[0]`.
- Fixes Proxy reload still showing graceful/timeout options instead of using force restart only.
- Fixes the business selector filtering by page actions and diverging from the business visibility scope.
- Fixes virtual user authentication errors being swallowed while requests continued with an empty username.
- Fixes config policy priority appearing in workflow logs.
- Fixes the File service not resolving the configured `gse.user` through user manager lookup.

**Agent / Plugin / Package compatibility**

- This release does not change Agent, Plugin, or Package formats.
- `hostIDPushMode: self` pushes the hostid file only during installation. The file contains only fields that Node Manager can determine: host ID, Network Area ID, first inner IP, Agent ID, addressing mode, and tenant ID. Later business topology or process changes are not synchronized, and the periodic synchronization behavior of `cmdb` mode is not provided.
- `hostIDPushMode` accepts only `cmdb` or `self`; an empty value means `cmdb`. An invalid value prevents Backend from starting.
- Global GSE Proxy network settings apply only to Linux; non-Linux Agents are unaffected.

**Component dependencies and upgrade prerequisites**

- To use the new system configuration queries, upgrade Backend, import and publish the corresponding API Gateway resources, and grant callers `platform_manage` on `system_config`.
- To use plugin workflow IP filtering, update and publish the API Gateway resources together with the service upgrade. Upgrading services does not expose gateway endpoints automatically.
- Configure `file.config.userManager` before upgrading File. BlueKing 7.3 resolves `login_name` through user manager lookup in both single-tenant and multi-tenant modes. BlueKing 7.2 single-tenant deployments must set `useLegacyUsername: true` in all three services; multi-tenant mode does not support this compatibility switch.
- After changing global GSE Proxy network settings, restart Backend and reconfigure existing Proxy nodes. Ports may be 0 to use defaults or 1-65535, and the resolved values must not conflict.
- The new plugin process expiry settings have defaults and do not require manual initialization; adjust them by alive-sync cycle as needed.
