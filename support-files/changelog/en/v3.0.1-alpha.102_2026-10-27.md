## [Version: v3.0.1-alpha.102] - 2026-10-27

Full Changelog: [v3.0.1-alpha.101...v3.0.1-alpha.102](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.101...v3.0.1-alpha.102)

> Important notes

- When importing a plugin package, each configuration template `filePath` must be a fixed directory: `etc` for the main configuration and `etc/<plugin_name>` for sub-configurations. Packages that do not match are rejected. Before upgrading, check `definition.yaml` (V3) or `project.yaml` (V2) in the packages you plan to import.
- Downloading Agent, Proxy, plugin, certificate, and bin tool packages requires the `package_view` permission for the corresponding package. Download requests fail when the backend authorization service is unavailable.

**Release scope**

- Backend/Control Plane: Adds V2 plugin installation limits, atomic config policy event snapshots, package download permission checks, and corrected APIGW request ID handling.
- Plugin/Package: V2 plugin packages can declare installation CPU and disk IO limits; plugin configuration template paths are fixed; upload results show the limits.
- Installer/Deployment: The Installer can configure the firewall before a full install on Windows and applies limits when unpacking V2 plugin packages; APIGW sync can publish an optional topology query MCP Server.
- Frontend: Improves out-of-band management settings and adds configurable out-of-band protocol options.

**New features**

- V2 plugin `project.yaml` accepts the optional `install_cpu_limit` (0 to 1) and `install_disk_io_limit` (MB/s) settings to limit processing speed for tgz packages during installation or upgrade. If unset or set to `0`, no limit is applied; an `install_cpu_limit` of `1` also means unlimited.
- Installer full install adds the `--firewall_features` and `--firewall_remote_ips` flags. On Windows, firewall rules are configured before installation for the selected features (`gse`, `nodemgr`) and allowed CIDRs; other operating systems skip this step. CIDRs are required when features are set.
- The package upload result page shows installation CPU and disk IO limits declared by plugin packages, and plugin release query responses retain them.
- The out-of-band management settings page supports configuring device type, protocol, IP, and port, with hints for each field. Protocol options come from Helm `application.config.front.opsOutBandProtocols`, a JSON-encoded list that defaults to `[]`.
- API Gateway sync can publish the read-only topology query MCP Server `topo` (business topology, cloud areas, network units, access points, graph nodes, and hosts; no create, update, or delete operations). It is controlled by the apigw-sync setting `ENABLE_SYNC_MCP_SERVERS`, which defaults to `false`.

**Improvements**

- Failed Plugin, Plugin V2, and Package workflow actions are retried with jittered backoff. Timeouts and retry counts remain unchanged; subsequent retries and final failure reporting may take longer.
- V3 plugin templates can read the sub-configuration directory (`<PluginHomeDir>/etc/<plugin_name>`) through `PluginInfo.SubConfigPath`.
- Improves the device dropdown on the out-of-band management page; protocol names no longer show port suffixes.
- The apigw-sync image is based on `apigw-manager:4.2.4`, and Helm `apigwSync.config` uses `spec_version: 2`.

**Bug fixes**

- Fixes config policy event records for create, update, delete, enable, disable, and reorder operations: events use atomic snapshots taken at operation time, and mutations that succeeded before a batch error are still recorded.
- Fixes mixed-up APIGW request ID headers: the server reads the gateway-generated `X-Bkapi-Request-Id`, and the client sends the business `X-Request-Id` to the gateway.
- Fixes plugin visibility queries omitting plugins whose `visible_biz_ids` is null.
- Fixes legacy V2 plugin installation and upgrade unpacking not applying CPU and disk IO limits.

**Agent / Plugin / Package compatibility**

- For V2 plugin packages, `install_cpu_limit` must be between 0 and 1 and `install_disk_io_limit` must be non-negative; invalid values fail package import.
- V2 plugin package import validates configuration template paths: `etc` for the main configuration and `etc/<plugin_name>` for sub-configurations. The same rule applies to V3 and external plugin packages.
- Plugin install and upgrade pass limit arguments to the Installer only when a limit is in effect (`install_cpu_limit` greater than 0 and less than 1, or `install_disk_io_limit` greater than 0). Packages without limits behave as before.
- Package download request and successful-response fields are unchanged; callers must hold `package_view` for the corresponding package.

**Component dependencies and upgrade prerequisites**

- To use V2 plugin installation limits, upgrade the Installer on target hosts to this version so it supports `--cpu-limit` and `--diskio-limit` and applies the limits while unpacking.
- To use Windows firewall configuration, upgrade the Installer to this version so it supports `--firewall_features` and `--firewall_remote_ips`. Verify that features and CIDRs are appropriate; use `/32` or `/128` for a single IPv4 or IPv6 address, respectively.
- Before upgrading, ensure operators and callers that download packages hold `package_view` for the corresponding `package` resource.
- To sync the topology MCP Server, upgrade the chart and the apigw-sync image together and set `ENABLE_SYNC_MCP_SERVERS` to `true`.
- To use out-of-band protocol options, configure the protocol list in Helm `application.config.front.opsOutBandProtocols`; protocol options are empty when it is unset.
