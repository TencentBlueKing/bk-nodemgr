## [Version: v3.0.1-alpha.20] - 2026-04-27

Full Changelog: [v3.0.1-alpha.19...v3.0.1-alpha.20](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.19...v3.0.1-alpha.20)

**Release Scope**

- Backend/Control Plane: Added Proxy assign unit APIs, workflow actions, and route wiring, enhanced OpenTelemetry tracing configuration, refactored and fixed global settings registration logic, and optimized syncdata task concurrency and performance
- Frontend: Added and integrated plugin installation and plugin operation flows, delivered Proxy assign unit pages and interactions, and updated related i18n resources and type definitions
- Installer/Deployment: Updated Helm templates with revision and `ttlSecondsAfterFinished` for sync jobs, and adjusted deployment configuration for multiple services

**New Features**

- Added Proxy assign unit capability across application/backend APIs, routing, and workflow actions, enabling end-to-end proxy assignment by unit
- Added plugin operation pages with step-based execution flow, and completed plugin installation related UI entry and execution preview support

**Optimizations**

- Enhanced OpenTelemetry observability with additional tracing configuration and request handling support to simplify cross-service request troubleshooting
- Optimized syncdata task performance with global settings driven controls, introducing concurrency control and tuning sync action execution behavior to reduce latency and congestion in large-scale scenarios
- Improved workflow execution scheduling and processing behavior for better stability and throughput

**Agent / Plugin / Package compatibility**

- No Agent / Plugin / Package version range or package format changes

**Component Dependencies and Upgrade Prerequisites**

- This release includes new Node Proxy API fields and workflow capabilities, ensure backend/application services and frontend are upgraded in a consistent rollout
- This release includes proto and swagger updates, for external integrations based on API schemas, update corresponding clients or validation logic accordingly
- When upgrading Helm to `v3.0.1-alpha.20`, verify the sync Job `revision` marker and `ttlSecondsAfterFinished` cleanup policy against current cluster requirements for Job retention and troubleshooting
