## [Version: v3.0.1-alpha.107] - 2026-11-10

Full Changelog: [v3.0.1-alpha.106...v3.0.1-alpha.107](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.106...v3.0.1-alpha.107)

> Important notes

- The encryption suite remains `CLASSIC` by default. Switching to `SHANGMI` or back to `CLASSIC` does not migrate existing ciphertext. Temporary host credentials saved under the other suite cannot be reused and must be entered again for installation. Returning to `CLASSIC` does not make SM4 credentials readable; reusing unexpired original AES credentials also requires the original `encryptKey`.
- Package operation history now checks `package_history_view` permissions by package type. Deployments with IAM enabled must synchronize permission models and corresponding grants when upgrading. For IAM V4, if this Action is already bound to `package`, explicitly replace its binding with `package_type`, then synchronize roles and verify grants for the new dimension; a regular upsert is insufficient. Replacement may remove existing permissions, and old grants are not migrated automatically.
- Alive plugin process synchronization URLs change from `/api/v3/sync/gse/plugin/process/info` and `/api/v3/sync/gse/plugin/process/info/all` to `/api/v3/sync/gse/plugin/process/info/alive` and `/api/v3/sync/gse/plugin/process/info/alive/all`. The old routes are no longer registered; direct callers must update their URLs.
- IAM V4 now caches allowed resource-free authorization results locally for 5 minutes. Revoked permissions may remain allowed until cache expiry. Denied results and IAM errors are not cached, so new grants incur no deny-cache delay. Resource-scoped checks do not use this cache.

**Release scope**

- Backend/Control Plane: GM credential encryption and outbound TLCP, compatible plugin deployment and configuration rendering, policy-owned artifact cleanup, plugin process state synchronization, GSE operation identities, package history authorization, and IAM V4 caching.
- API Gateway/MCP: Read-only topology queries now use user-context open APIs.
- Application/Frontend: Encryption suite integration, browser local storage isolation by tenant and user, and interaction restrictions for the unassigned Network Area.
- File: Package metadata caching and cache invalidation across replicas.
- Installer/Deployment: Multiple main plugin configurations, sub-configuration preservation and renewal controls, GM deployment settings, and Redis integration for the File service.

**New features**

- Plugin installation and upgrades support multiple main configuration files for both V3 and legacy V2 plugins. All main configurations for a plugin share the custom rendering context, and configuration file names must be unique.
- Supports the `SHANGMI` suite: SM2 encrypts credentials in transit, and SM4-GCM encrypts temporary credentials at rest. The new unified public key API, `Cipher_GetCurrentPublicKey`, lets callers select the algorithm using `key_type`. Outbound API Gateway clients can opt into TLCP individually.
- `ensure_absent` deployment policies can clean up policy-owned plugin package deployments and sub-configurations, covering plugin package, plugin package projection, and both sub-configuration spec types. Matching artifacts in previous deployment scopes or on previous hosts are included, regardless of version or running status.
- Adds synchronization for stopped plugin process information, supporting selected hosts, tenant-wide runs, and scheduled runs every 10 minutes by default. Local `stopped` records are checked against GSE and marked `unknown` when the Agent is offline or GSE no longer reports the process. A returned `trigger_id` indicates task submission, not completion; check execution results.

**Improvements**

- The File service caches package metadata queries locally and uses Redis markers to invalidate cached data across File replicas within a tenant after writes. If an invalidation marker write fails, existing cached data expires after its one-minute TTL.
- In compatibility mode, upgrading a V3 plugin also aligns its legacy V2 plugin to the target version. If the running version is empty or different, the old process is stopped before installing the target version; existing sub-configurations are preserved during the upgrade.
- Plugin installers support preserving or renewing sub-configurations as needed. Newly deployed configurations take precedence over preserved files with the same name. Regular V3 APIs, pre-installed plugins, and deployment policies still renew sub-configurations rather than universally preserving them.
- V3 plugin package configuration templates may omit `filePath` or leave it empty. It defaults to `etc` for main configurations or `etc/<plugin_name>` for sub-configurations. Explicit paths must still match these fixed directories.
- Browser local storage is isolated by tenant and login user, preventing preference data from leaking between identically named users in different tenants.
- The topology MCP binds its 11 read-only queries to user-context APIs under `/api/v3/open/topo/*`, retaining user identity, system access, and resource permission checks without adding write operations. Deployments using this MCP must synchronize API Gateway resources and the MCP definition.

**Bug fixes**

- Fixed upload results for legacy V2 plugin packages and external plugin packages returning the uploaded file name instead of the plugin package name.
- Standardized Network Area page routes: `workarea` and `workarea-detail` become `networkarea` and `networkarea-detail`. Update existing bookmarks and external page links; the old routes are no longer registered.
- Fixed template expressions in custom plugin configuration context not being rendered before configuration templates, affecting both V3 and legacy V2 plugins.
- Fixed plugin process and file operations incorrectly using the installation login user. GSE operations default to `root` on Unix-like systems and `system` on Windows; installation login users and the template `account` variable retain their existing meanings.
- Fixed missing permission-scope filtering in package operation history lists and counts. Only records for authorized package types are returned.
- Restricted detail access, topology selection, and Network Unit creation and assignment for the unassigned Network Area in the UI, preventing it from being used as an ordinary Network Area.

**Agent / Plugin / Package compatibility**

- The legacy RSA public key API remains available. RSA-only callers must use `CLASSIC`; callers must adopt the unified public key API and SM2 before enabling `SHANGMI`. Refresh open credential entry pages after switching suites to fetch the current public key.
- V2 compatibility upgrades require the legacy plugin package for the target version. A version mismatch stops the old process; this is not a zero-downtime upgrade.
- `ensure_absent` does not yet support `specify_plugin` or Agent/Proxy. Sub-configuration deletion requires a running plugin process. Task submission does not mean cleanup has completed; check execution results. Do not configure conflicting forward and reverse policies for the same artifact.

**Component dependencies and upgrade prerequisites**

- The File service now requires Redis configuration and checks connectivity at startup. Helm uses the embedded Redis or `externalRedis` settings. Deployments with manually maintained service configurations must add the File service `redis` settings; the service cannot start if the connection is unavailable.
- The plugin main configuration callback changes from a single-file response to a JSON file list. Upgrade Backend and plugin installers (V3/V2) together to avoid incompatible callback formats.
- Upgrade Backend, Application, and Frontend together to use GM support. Enable it with `backend.config.cryptoType: SHANGMI` in Helm or `BK_NODEMGR_BACKEND_CRYPTO_TYPE=SHANGMI` in Docker Compose. The default `CLASSIC` suite retains the existing RSA/AES behavior.
- TLCP requires a compatible endpoint and a CA, signing certificate/key pair, and encryption certificate/key pair configured for the client. Mount certificate files into the service container. Without an encryption pair, clients retain standard TLS. TLCP is outbound-client only; it does not cover server listeners, infrastructure connections, or JWT algorithm replacement.
- For IAM V4 binding replacement, role restoration, and grant verification, see the [permission model migration guide](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.107/support-files/bkiamv4/README.md#显式替换-action-绑定).
