## [Version: v3.0.1-alpha.86] - 2026-09-17

Full Changelog: [v3.0.1-alpha.85...v3.0.1-alpha.86](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.85...v3.0.1-alpha.86)

**Release scope**

- Backend/Control Plane: Plugin, Package, Sync, Deploy Policy, IAM v4, Workflow, and Tracing handling.
- API Gateway: Sync resource documentation and resource definitions.
- Installer/Deployment: Helm and docker-compose tracing configuration, plus optional embedded Tempo and OpenTelemetry Gateway deployment support.

**New features**

- Added Sync APIs for manually ensuring default Plugins and synchronizing shared Releases, with API Gateway resources and localized API documents.
- Added OTLP HTTP tracing exporter configuration for Helm and docker-compose deployments.
- Added optional embedded Tempo and OpenTelemetry Collector Gateway support to the Helm chart for Node Manager self-monitoring and tracing fan-out.

**Improvements**

- Package Release responses now include name fields for clearer artifact display in frontend and API clients.
- Improved process configuration cleanup during plugin uninstall workflows, including the Plugin V2 uninstall path.
- Preserved IAM v4 resource attributes so authorization requests keep their resource context.

**Bug fixes**

- Release brief APIs skip Package authorization checks to avoid failing summary queries on package permission checks.
- Deploy policy workflow ID `0` is accepted as valid data instead of being filtered or interrupted.
- Stale workflow trigger cache entries are skipped when reading workflow trigger records.
- Empty downstream service error responses are handled without losing error context.

**Agent / Plugin / Package compatibility**

- This version does not change Agent / Proxy, Plugin, or Package formats.

**Component dependencies and upgrade prerequisites**

- Tempo and OpenTelemetry Gateway are optional Helm capabilities and remain disabled by default.
- This version does not introduce mandatory upgrade prerequisites.
