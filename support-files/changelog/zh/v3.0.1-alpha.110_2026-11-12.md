## [Version: v3.0.1-alpha.110] - 2026-11-12

Full Changelog: [v3.0.1-alpha.109...v3.0.1-alpha.110](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.109...v3.0.1-alpha.110)

> 重要提示

- IAM V3 显式替换 Action 资源绑定改为删除旧 Action 后重建，不再原位更新。既有 `--allow-action-replace` 仍默认关闭；策略删除不可逆，旧授权不会自动转换，删除与重建之间 Action 暂时不可用。该流程没有事务或自动回滚，执行前确认系统、租户及受影响的用户／用户组，执行后重新配置并验证新资源维度的权限。
- 操作分组、常用操作和新建关联等引用可能阻塞 Action 删除，工具不自动清理这些配置。重建后需同步并核对 `0003`～`0005` 中的相关配置，不能再依赖原位更新保留引用。

**发布范围**

- Backend/Control Plane：IAM V3 模型迁移工具的 Action 绑定替换修复、File 服务多平台包生成与发布的并发崩溃修复，以及版本日志的发布阶段识别调整。
- Frontend：管控单元自定义部署配置的路径校验与错误定位。
- Installer/Deployment：IAM V3 模型同步的升级与恢复说明。

**功能优化**

- 版本日志按项目版本格式识别 `alpha`、`beta`、`release` 阶段，支持带可选标记的版本号；`rc` 阶段不再接受，既有 `rc` 版本的日志文件不再列出，详情查询也不再接受该版本号。
- 管控单元表单按操作系统校验自定义部署路径：Unix-like 路径须以 `/` 开头且不含控制字符；Windows 支持盘符绝对路径或 UNC 路径，拒绝非法字符和保留名称。提交时定位到路径错误对应的操作系统及字段；Windows IPC 端口不作为文件路径校验。

**缺陷修复**

- 修复 File 服务在多平台包生成或发布时，因并发写入 map 触发 `fatal error: concurrent map writes` 并导致进程退出的问题，覆盖 Agent、Proxy、服务端包生成 Proxy，以及 V3 插件、旧版 V2 插件和外部插件包；无需数据迁移。
- 修复 IAM V3 Action 资源绑定变化时原位更新失败的问题。显式允许替换后，先校验目标定义，再提交策略清理、删除旧 Action，确认旧 Action 已不存在后重建；重建保留请求中未提供的现有可写字段。绑定不变时仍普通更新，不清理策略或删除 Action。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式，也不变更 API / Proto 契约。

**组件依赖与升级前置条件**

- IAM V3 策略清理要求 IAM SaaS ≥ 1.4.15、后台 ≥ 1.7.7；不支持时迁移停止。替换开关作用于选定文件或目录中所有发生绑定变化的 `upsert_action`，不改变显式 `update_action` 的行为；执行前检查全部改绑范围，必要时使用 `-f` 缩小范围。`--dry-run` 仅列出文件，不查询模型或验证依赖及策略影响。
- 策略清理与 Action 删除可能异步执行，接口成功不代表完成。工具仅提交一次清理和删除请求，等待确认旧 Action 消失后才创建；删除失败、查询失败或等待超时即停止，不尝试创建或自动重发删除请求。失败或结果未知时先检查远端状态，不要盲目重试。
- `package_history_view` 旧绑定迁移到 `package_type` 后，需重新配置并验证 `package_type` 维度权限。Action 已删除、已是目标绑定或仍是旧绑定时的恢复步骤，见 [IAM V3 迁移说明](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.110/support-files/bkiamv3/README.md#显式替换-action-资源绑定)。
