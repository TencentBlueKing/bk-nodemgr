## [Version: v3.0.1-alpha.24] - 2026-05-14

Full Changelog: [v3.0.1-alpha.23...v3.0.1-alpha.24](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.23...v3.0.1-alpha.24)

**发布范围**

- Agent: 升级链路支持在未显式指定版本时自动选择默认版本，优化节点列表首屏加载和升级请求传参。
- Proxy: 升级请求改为按主机传递目标版本，补强预装插件安装时的发布包与安装器传输。
- Plugin: 优化参数配置与进程操作页交互，增强多 namespace 进程处理和进程停止逻辑。
- Package: 无独立发布包格式调整，默认版本选择与预装插件安装依赖现有发布包元数据。
- Backend/Control Plane: 提升主机同步容错、workflow tracing 与 retry handling、策略配置查看链路稳定性。
- Installer/Deployment: Relay `--version` 输出改为更适合脚本和发布链路消费的纯版本字符串。

**新增功能**

- Agent 升级链路支持在请求未显式携带目标版本时自动选择系统默认版本，便于按平台直接发起标准升级。
- Proxy 升级链路支持按主机携带目标版本，适配混合平台批量升级和跨页选主机场景。
- Proxy 预装插件安装链路补齐发布包、安装器和离线主配置文件传输，降低代理节点安装后追加插件失败概率。
- Plugin 进程处理链路适配 multi-namespace proc handler，为多 namespace 的进程托管和控制提供支持。

**功能优化**

- Plugin 参数配置页面优化版本选择、SchemaForm 初始化和设置面板展示，减少无效 warning 并提升参数卡片可读性。
- Agent 节点列表改为异步加载筛选条件，缩短首屏等待时间。
- Workflow 执行链路补强 tracing 与 retry handling，提升后台动作执行稳定性。
- Relay 版本输出格式调整为纯版本字符串，便于发布检查和脚本读取。

**缺陷修复**

- Plugin 进程停止逻辑改为结合主机状态判断，减少异常主机上的无效停止操作。
- 策略配置项页面修复新增入口和查看态交互异常，避免只读场景仍显示可编辑动作。
- sync_host 在遇到偶发重复主机数据时改为容忍并继续同步，降低全量同步失败风险。
- 安装表格修复样式与校验单元格展示问题，改善安装页可读性。
- Proxy 升级请求修复目标版本传递位置，避免多平台主机升级时出现版本映射偏差。

**Agent / Plugin / Package compatibility**

- Agent 与 Proxy 升级增强依赖新版升级 API、协议字段、swagger 与 API Gateway 资源保持一致，调用端需要按最新请求结构传递每台主机的目标版本，或允许系统回填默认版本。
- Proxy 预装插件安装增强依赖现有发布包、安装器和离线配置文件同时可用，离线或间接安装场景建议同步升级对应的 Backend 与 Frontend。
- Plugin 多 namespace 进程处理依赖现有 GSE 进程托管信息按 namespace 返回，灰度环境建议先验证现有进程定义与托管结果。

**组件依赖与升级前置条件**

- 默认版本自动选择依赖目标平台的发布包元数据完整可用，升级前需确认对应 OS 和 CPU Arch 已发布默认版本。
- Proxy 按主机传递目标版本的升级请求需要 Frontend、Backend 和 proto 定义保持一致，避免旧调用端继续沿用旧字段结构。
- Plugin 参数配置优化涉及版本选择、参数表单和进程操作页联动，升级后建议同时部署新版前端资源以获得完整交互效果。
