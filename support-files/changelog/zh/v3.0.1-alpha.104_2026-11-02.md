## [Version: v3.0.1-alpha.104] - 2026-11-02

Full Changelog: [v3.0.1-alpha.103...v3.0.1-alpha.104](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.103...v3.0.1-alpha.104)

> 重要提示

- Helm 部署的 Application、Backend、File 日志目录统一使用 `common.logPath`，默认值由 `/bk-nodemgr/logs` 改为 `/bk-nodemgr/log`；各组件 `config.log.dir` 不再生效。自定义日志目录的环境需将配置迁移至 `common.logPath`，并同步调整挂载及外部采集路径。
- `ensure_absent=true` 的部署策略不再按正向部署处理；反向清理尚未实现，包含 spec 的反向策略在执行或预览计算时返回错误，同次计算中的相关正向策略也不会继续。升级前检查已启用策略；需要正向部署时将该字段恢复为 `false`，不要将其用于卸载或删除配置。
- 自定义安装/升级脚本需调整：adminclient 的 `bkapp code/secret` 必须携带凭证名 `iamv3`、`iamv4` 或 `apigw-sync`；`init_package.py` 移除 `--jwt-key`、`--expire-hours`，改由 adminclient 按 File 配置签发有效期固定为 24 小时的 JWT。独立 `jwt-generator` 不再提供。
- 存量 `process_config_<tenantID>` 集合的旧三字段唯一索引不会自动删除，仍会阻止同名主子配置共存。使用该能力前，需备份数据、确认四字段唯一索引（含 `data.is_main_config`）建立成功，再移除对应旧三字段唯一索引；已有同名主子记录时，不能直接恢复旧唯一索引或依赖旧版按名称处理配置。

**发布范围**

- Backend/Control Plane：部署策略方向处理、插件部署准备查询、同名主子配置区分。
- File：V3、旧版 V2 及 V2 外部插件包的配置模板重名校验，V3/旧版 V2 发布包自定义文件保留。
- Application：Web/SaaS 请求 ID 处理；Backend：Proxy 安装主机查询。
- Installer/Deployment：Helm 日志目录统一及可选蓝鲸日志采集配置、adminclient 凭证解析、初始化包导入和 IAM/API Gateway 同步。
- Frontend：Agent/Proxy 带外管理当前设置回显、主控机选择与分页。

**新增功能**

- Helm 新增 `bkLogConfig.enabled`，默认关闭；启用后创建标准输出和容器文件日志两类 `BkLogConfig`，采集带时间戳的 System/Business INFO 日志文件。

**功能优化**

- 生成 V3 和旧版 V2 插件发布包时，保留对应平台插件目录内的自定义普通文件、相对路径和源文件权限，支持随包携带依赖库及辅助资源。
- 插件部署准备阶段批量读取主机和插件，并在单次请求内去重默认版本及资源包发布信息查询，减少批量部署中的重复查询。
- Agent/Proxy 带外管理表格加载当前设置，回显主控机 IP 和选择状态，并保留已有自定义带外协议。
- adminclient 的 JWT 签发和应用凭证读取同时支持 KMS 与明文部署，初始化包导入及 Helm 同步 Job 统一使用该入口；服务配置自动发现同时支持 Helm 的 `*_conf.yaml` 和 Docker Compose 的 `bk-nodemgr-*.yml`。

**缺陷修复**

- 修复 Application Web/SaaS 请求 ID 处理：读取 `X-Request-Id`，缺失时生成请求 ID，便于关联请求日志。
- 修复 Proxy 安装中目标主机 ID 集合为空时仍查询已有主机的问题，避免空条件引发无关主机查询。
- 修复切换顶部业务后主控机选择器拓扑未刷新的问题；IP 选择器默认每页条数固定为 10。
- 修复 `ensure_absent=true` 仍进入正向部署计算的问题，改为明确拒绝尚未实现的反向操作。
- 修复同名主配置与子配置在模板匹配、部署记录更新及策略计算中相互覆盖的问题；删除子配置时仅匹配子配置文件和记录，避免影响同名主配置。

**Agent / Plugin / Package compatibility**

- 本版本不涉及 Agent 安装器、插件包格式或资源包版本要求变更。
- 自定义文件保留仅作用于新生成的 V3/旧版 V2 发布包，不回填已有发布包，也不扩展 V2 外部插件打包流程。仅复制普通文件，不保留符号链接、硬链接或空目录；V3 的 `definition.yaml`、`templates/*.template` 和 V2 的 `project.yaml`、`etc/*.tpl` 不作为自定义文件复制，标准文件仍按原规则处理。
- 自定义文件不得与生成包中的标准文件或 bintool 文件重名；打包不会统一检查目标路径冲突。新增复制路径会拒绝绝对路径及不合法路径片段，但不校验自定义文件内容；发布前需核对来源、内容、权限和目标路径。
- 同一平台内允许主配置与子配置模板同名，但同一类型内模板名重复的 V3、旧版 V2 及 V2 外部插件包导入将被拒绝，需修正重复声明后重新导入。
- 配置记录沿用已有 `is_main_config` 字段，不会自动修复此前已被覆盖的内容或回填缺失的主子标记；存量异常记录需按实际主子归属核对修复后再执行配置操作。

**组件依赖与升级前置条件**

- 安装文档补充服务运行模式迁移说明：旧配置中的 Application、Backend、File 服务级 `mode` 需改为 `runMode`（Helm 使用 `<service>.config.runMode`），生产环境使用 `release`；旧键不能设置服务运行模式。此说明不涉及第三方组件的其他 `mode` 字段。
- Frontend 的当前设置回显依赖已有 Agent/Proxy 带外字段查询接口；配套 Backend/Application 至少使用 `v3.0.1-alpha.103` 中提供该接口的版本。
- 启用 `bkLogConfig.enabled` 前，需安装支持 `bk.tencent.com/v1alpha1` 的 `BkLogConfig` CRD 和对应日志采集服务，并将 `bkLogConfig.dataId` 设置为目标采集 Data ID；不使用该能力时保持关闭。
- 启用 JWT 鉴权的初始化包导入及 Helm IAM/API Gateway 同步需配套提供新版 `bk-nodemgr-adminclient` 的镜像；手工导入时需可执行该二进制并提供 File 配置，非标准配置文件名使用 `--config-file` 显式指定。
- KMS 模式下，凭证解析需可读的 global envelope 和 `BK_NODEMGR_KMS_PRIVATE_KEY_GLOBAL`，解密失败不会回退到明文。明文模式下，JWT 鉴权需配置非空的 `<server>Server.jwtServerConfig.symmetricKey`；IAM 同步凭证来自 Backend 的 `iamV3/iamV4.appCode/appSecret`，API Gateway 同步凭证来自 Job 环境变量 `BK_APP_CODE`、`BK_APP_SECRET`（通过 `apigwSync.extraEnvVars` 注入）。

**已知问题**

- 带外设置回显查询失败时，表格仍可展示和提交，但当前设置可能为空；跨页全选的主机查询中断时，仅展示已加载的主机。提交前核对设置和主机范围，异常时重新加载，避免将空字段覆盖到现有配置或遗漏目标主机。
