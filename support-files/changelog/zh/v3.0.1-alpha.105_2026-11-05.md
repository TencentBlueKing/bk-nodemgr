## [Version: v3.0.1-alpha.105] - 2026-11-05

Full Changelog: [v3.0.1-alpha.104...v3.0.1-alpha.105](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.104...v3.0.1-alpha.105)

> 重要提示

- 插件安装、升级接口移除 `plugin[n].config_template_name`，改为自动下发目标发布包的全部主配置；对接方需移除该参数，子配置改用独立下发接口。调试接口仍保留该参数，但仅用于追加子配置模板，传入主配置模板名会导致任务失败。
- 安装、升级请求同时调整了 `custom_config_context` 及安装请求 `custom_spec` 的 Protobuf 字段编号，不兼容旧版二进制消息。需配套升级 Backend、Application，重新生成相关客户端并同步 API Gateway 资源，避免混用新旧 Protobuf 定义。

**发布范围**

- Backend/Control Plane：插件主配置自动下发、子配置组合选项持久化、拓扑请求定义及 CMDB 错误提示。
- Application/Frontend：按环境配置平台公共资源、配置策略选项说明及 Agent/Proxy 包上传错误展示。
- Installer/Deployment：Helm、Helmfile 和 Docker Compose 的 Application 配置，以及 FileProxy 配置策略选项。

**新增功能**

- Proxy 配置策略新增 FileProxy BT 监听绑定选项 `file.bittorrent.bind_ip`，可填写 IP 或网卡名；默认不启用，选项预设值为 `0.0.0.0`。
- 支持通过 Application `front.bkSharedResBaseJSURL` 按部署环境加载平台 Logo、标题和页脚等公共配置，无需重新构建 Frontend；留空时使用默认平台配置。
- API Gateway 资源新增 9 个已有 OpenNodeAgent 接口、2 个节点操作历史接口，以及插件配置文件查询和子配置移除接口；既有接口权限配置保持不变。

**功能优化**

- V3 插件安装、升级、调试及旧版 V2 插件 Ensure 部署自动读取发布包中的全部主配置模板，不再仅在配置列表为空时补入首个主配置。发布包没有主配置模板时不额外生成主配置。
- 插件部署记录可保存目标子配置的插件名、管理集合、模板、渲染变量及源插件绑定 IP/端口的变量映射，与源插件配置独立存储；本次仅增加持久化支持，不新增子配置组合执行入口。
- 配置策略选项增加中英文悬浮说明；OpenNodeAgent 补齐已有开放接口的 Proto/Swagger 描述，不新增运行时路由或节点操作能力。

**缺陷修复**

- 修正拓扑图节点查询的请求定义，API Gateway Schema 和 Frontend 客户端不再误用响应结构作为请求结构。
- Agent/Proxy 包上传失败时，在上传卡片及提示中展示后端具体原因；修复长错误信息被裁切及网络错误后未正确显示失败状态的问题。
- CMDB 默认管控区域（云区域 0）已有相同内网 IP 时，明确提示复用已有主机或先清理冲突记录；不改变 CMDB 的冲突校验规则。
- 修复通知文字未保持左对齐的问题；Frontend 插件安装、升级请求同步移除 `config_template_name`。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent 安装器或插件包格式。主配置自动下发依赖发布包中正确的主配置标记；不会自动修改已导入包的模板标记。
- 历史插件部署记录缺少子配置组合选项时按空选项读取，不自动回填；此前丢失或被覆盖的配置内容不会恢复。

**组件依赖与升级前置条件**

- 继续遵循 alpha.104 的同名主子配置索引要求：存量 `process_config_<tenantID>` 集合需备份数据、确认含 `data.is_main_config` 的四字段唯一索引建立成功后，再移除旧三字段唯一索引；旧索引不会自动删除。缺失主子标记的历史记录需先核对修复；已有同名主子记录时不能直接恢复旧索引或回退到旧版按名称处理配置。
- 平台公共资源配置需配套升级 Application 和 Frontend。Helm/Helmfile 使用 `application.config.front.bkSharedResBaseJSURL`，Docker Compose 使用 `BK_NODEMGR_APPLICATION_SHARED_RES_BASE_JS_URL`，并提供浏览器可访问的公共资源地址。
- 使用新的 FileProxy 选项需更新 Application 配置策略清单及 Frontend；通过 `application.config.configPolicyOption.proxyOption` 或自定义文件覆盖内置清单的环境，需同步加入该选项。保存策略不会自动重配已有 Proxy，需执行相应配置下发使其生效。
