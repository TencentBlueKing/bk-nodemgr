## [Version: v3.0.1-alpha.109] - 2026-11-11

Full Changelog: [v3.0.1-alpha.108...v3.0.1-alpha.109](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.108...v3.0.1-alpha.109)

> 重要提示

- IAM V3 与 V4 的 Action 绑定替换机制不同：V3 清理该 Action 的策略后原位更新，不删除 Action；V4 删除旧 Action 后重建。两者均需显式允许，旧授权不会自动迁移，失败不自动回滚；执行前确认目标系统、租户和授权影响，执行后重新配置并验证新维度权限。
- IAM V4 自动替换现在会移除角色中的旧 Action 成员；后续角色同步仅恢复模板声明的成员，自定义角色中未在模板声明的成员需单独恢复。不自动清理 RBAC/ABAC 授权，其他依赖冲突仍会阻塞替换。

**发布范围**

- Backend/Control Plane：IAM V3 模型迁移工具的显式绑定替换、IAM V4 自动替换的角色成员清理，以及插件包发布结果的平台过滤。
- Installer/Deployment：IAM 模型同步的升级与恢复说明，以及 API Gateway MCP 同步 stage 覆盖排障文档。

**新增功能**

- IAM V3 迁移工具新增 `--allow-action-replace`，默认关闭。`upsert_action` 遇到资源绑定变化时默认停止；显式启用后先校验目标定义，再清理策略并原位更新，保留操作分组、常用操作等对 Action 的引用。绑定不变时不清理策略；开关适用于选定文件或目录中的全部改绑 `upsert_action`，不改变显式 `update_action` 的行为。

**功能优化**

- 补充启用 MCP 同步后报 `mcp_servers: 该字段是必填项` 的排障说明：覆盖 `apigwSync.config.stages` 会整体替换默认列表，各 stage 需补齐非空的 `mcp_servers`。本次仅更新文档，不改变同步行为；重跑同步 Job 会同步资源并可能发布版本，不是只读验证。

**缺陷修复**

- 修复 IAM V4 自动替换 Action 时角色成员引用阻塞删除的问题：既有 `--allow-action-replace`／Helm `iamV4.option.allowActionReplace` 启用后，使用 `cascade: ["role"]` 清理成员并删除重建。开关仍默认关闭；显式 `replace_action` 未声明 `cascade` 时仍不级联。
- 修复同名同版本插件包已发布其他平台后，本次上传因混入其他平台记录而校验失败的问题。发布结果按本次上传平台过滤，覆盖 V3 插件、旧版 V2 插件及外部插件包。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式；插件包发布仍须匹配本次上传的平台集合。

**组件依赖与升级前置条件**

- IAM V3 策略清理要求 IAM SaaS ≥ 1.4.15、后台 ≥ 1.7.7；不支持时迁移停止。策略删除不可逆，`--dry-run` 仅列出文件，不查询模型或验证策略影响。清理成功但更新失败时，先检查远端状态，不要盲目重试。
- IAM V3 的 `package_history_view` 在基础模板中直接绑定 `package_type`；旧绑定首次迁移需显式允许替换。重新渲染到空输出目录，避免已删除的独立改绑模板对应的旧 JSON 残留；操作及恢复限制见 [IAM V3 迁移说明](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.109/support-files/bkiamv3/README.md#显式替换-action-资源绑定)。
- IAM V4 自动替换需使用包含角色级联清理逻辑的 Backend 工具镜像。`--dry-run` 只查询模型并输出计划，不调用删除接口，不能证明依赖允许删除；替换后同步角色并核验授权，恢复步骤见 [IAM V4 迁移说明](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.109/support-files/bkiamv4/README.md#显式替换-action-绑定)。
