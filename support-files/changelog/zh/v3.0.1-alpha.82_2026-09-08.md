## [Version: v3.0.1-alpha.82] - 2026-09-08

Full Changelog: [v3.0.1-alpha.81...v3.0.1-alpha.82](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.81...v3.0.1-alpha.82)

> 重要提示

- release 元数据、BKRepo 文件目录和包下载路径改为租户隔离，升级后不再回退读取旧的共享 release collection。存量包环境需先确认数据迁移方案，不能仅升级服务后直接沿用旧路径。
- 升级或回滚前停止投递新任务并等待在途任务结束；Backend、File Service、Relay 与 installer 需配套切换，避免混用新旧下载路径、接收包通知和插件临时目录。

**发布范围**

- Agent / Proxy: 安装下载链路、Relay 文件传输与默认端口处理。
- Plugin: 按租户启用插件，分离 v2/v3 临时数据。
- Package: 租户隔离存储、证书包导入与上传体验。
- Backend/Control Plane: 包管理、任务详情与执行日志页面。
- Installer/Deployment: 插件临时目录切换与 IAM v4 资源类型迁移工具。

**新增功能**

- 插件启用仅为当前租户创建默认插件，不再向所有租户批量创建，各租户独立管理启用状态。
- 证书 `.tgz` 包支持将证书文件直接放在归档根目录；发布时统一生成 `cert/` 目录结构。
- IAM v4 迁移工具新增四类资源类型的注册和名称更新，保留管控区域与管控节点、包类型与包的父子关系，并支持 `--dry-run`。

**功能优化**

- 包元数据及 BKRepo 的 origin、release、export 文件按租户隔离，安装下载 URL 携带租户路径。
- Relay 安装包缓存支持重启恢复、过期清理和容量配置；调整安装关键步骤的超时与重试，提高批量安装稳定性。
- 包上传编辑后退出增加确认提示；补充 Agent、Proxy、Plugin、证书和工具包的导入格式 FAQ。

**缺陷修复**

- 修复 Relay 并发传包临时文件冲突、缓存完整性校验和消息 ACK 等待问题。
- 修复 Plugin v2/v3 并发执行时包、配置、默认日志和状态文件互相覆盖的问题。
- 修复任务详情跨页全选、IP 复制、执行日志跳转与筛选问题，以及通知栏无法关闭的问题。
- Proxy 重装按高级选项中指定的安装源应用到所有行；Relay 端口未指定或为 0 时使用回调端口 `28302`、下载端口 `28303`。

**Agent / Plugin / Package compatibility**

- 证书包仍支持 `cert/` 目录，但拒绝在根目录与 `cert/` 中混放证书文件；Agent / Proxy 与 Plugin 包格式不变。
- Plugin 临时数据改为 `data/plugin/v2` 和 `data/plugin/v3`，正式部署目录与工作目录不变，不自动读取旧共享临时目录。显式指定的共享 `log_dir` 和同版本同名任务冲突不在本次隔离范围内。
- Relay 接收包通知改为携带文件列表和 MD5；新 Relay 拒绝缺少校验信息的包，Backend 与 Relay 不应混用旧版组件。

**组件依赖与升级前置条件**

- release collection 从 `release_{type}` 改为 `release_{type}_{tenantID}`，BKRepo 目录增加 `/{tenantID}/` 前缀，File Service 下载路由改为 `/{tenant_id}/api/v3/...`。更新下载调用方及转发规则，并验证各租户包查询、下载和导出。
- **待确认**: 存量 release 元数据和 BKRepo 文件的租户归属、迁移步骤及回滚方案。升级前须完成方案确认与验证。
- Plugin 回滚也需配套回滚 Backend 与 installer，并重新投递旧路径所需的包和配置。
- 使用 IAM v4 迁移工具前先执行 `--dry-run`；祖先链冲突会停止迁移，已完成操作不会自动回滚。工具仍不迁移操作、角色和授权，启用 IAM v4 前需另行完成权限配置与验证。
