## [Version: v3.0.1-alpha.100] - 2026-10-20

Full Changelog: [v3.0.1-alpha.99...v3.0.1-alpha.100](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.99...v3.0.1-alpha.100)

**发布范围**

- Backend/Control Plane：插件安装和其他 V1 插件操作 workflow 支持并发限流；新增对应 Global Settings；KMS TLS 配置加载与校验调整。
- File Service：导入和发布前校验包结构；V3 插件 `project.yaml` 支持 `installCpuLimit`。
- Installer：新增 `--cpu-limit` 参数；增加 trace 关联。
- Deployment：Helm init container 改为通过 `bk-nodemgr-adminclient database check` 检查存储；adminclient 新增 `database` 子命令。
- Relay Plugin：暴露 APM tracing 配置。
- Frontend：优化权限申请、菜单权限校验和任务历史时间筛选。

**新增功能**

- 插件 V3 `project.yaml` 新增 `installCpuLimit`，用于控制 installer 在插件 install/upgrade 时处理 tgz 包的 CPU 比例。仅当取值满足 `0 < installCpuLimit < 1` 时，Backend 才会在生成的 install/upgrade 脚本中注入 `--cpu-limit`；未配置、`0` 或 `1` 时行为不变；V2 插件包忽略该字段。
- installer 新增全局参数 `--cpu-limit`，用于限制 Agent/Plugin tgz 压缩、解压过程中的 CPU 占用，降低单核机器或 cgroup 受限容器被占满的风险。该参数不限制磁盘 IO，不覆盖 `pluginv2` 子命令。
- installer 启动时生成 root trace 并打印 `trace-id`，对外 HTTP 请求注入 W3C `traceparent`，便于与服务端日志和 APM 关联。installer 不主动上报 span 数据。
- 新增 Global Setting `oper_plugin_install_max_concurrency_num`，默认值 `200`。每个插件安装 workflow 按该值限制自身并发数，不同 workflow 之间不共享限流。该限流仅适用于 v1 插件安装路径。
- V1 插件的 upgrade、uninstall、apply/remove sub config、start/restart/stop process、migrate from v2 和 start debug 操作改用 ordered trigger，并分别使用 `oper_plugin_<operation>_max_concurrency_num` 控制单个 workflow 的最大并发数，默认值均为 `200`。并发数在创建 workflow 时固定，修改 setting 只影响后续创建的 workflow；Plugin V2、node 和 package 导入操作不在本次范围内。
- adminclient 新增 `database` 子命令，支持 etcd、Redis、MongoDB 的连通性检查与连接，adminclient 配置支持从 KMS 获取。运维脚本 `script_tools/ops/{etcd,mongo,redis}.sh` 改为通过该子命令连接存储。
- relay 插件配置新增 APM tracing 选项：exporter 类型、OTLP endpoint、protocol、insecure、headers、service name 和 trace sample rate。未配置时保持原有行为。

**功能优化**

- File Service 在导入和发布 Agent、Server、Plugin、bintool、plugin_bintool 与证书包前校验包结构：拒绝空包、缺少必需文件、未知平台以及已提供平台内容不完整的包；证书包要求八个文件齐全、非空且位于根目录或 `cert/`。plugin_bintool 仅发布实际提供的代际。
- Helm 部署中 backend、application、file 的存储 init container 改为通过 `bk-nodemgr-adminclient database check` 检查 etcd 与 MongoDB，持续重试直至存储就绪，避免首次安装时因存储启动较慢出现 `Init:CrashLoopBackOff`。
- 调整 TLS 文件加载行为；非 enabled 的 TLS 配置不再参与转换与校验。
- 前端优化：申请管控单元权限时关联资源实例描述；左侧菜单与业务关联的权限校验；拓扑图中管控单元权限申请；任务历史按时间筛选。
- 前端、安装镜像 Dockerfile 声明 `# syntax=docker/dockerfile:1`，避免不同构建环境默认 parser 不一致导致构建失败。

**Agent / Plugin / Package compatibility**

- 本版本不修改 Agent、Plugin 或 Package 格式；`installCpuLimit` 为 V3 插件 `project.yaml` 的可选字段。
- 包结构校验可能拒绝此前可导入但结构不完整的包，请在导入前确认包内容完整。
- 本版本不修改 API Gateway 资源定义。

**组件依赖与升级前置条件**

- Helm 部署的 init container 依赖镜像内的 `bk-nodemgr-adminclient`，请同时升级各模块镜像与 chart。
- `--cpu-limit` 需使用本版本 installer；旧版 installer 不识别该参数。
