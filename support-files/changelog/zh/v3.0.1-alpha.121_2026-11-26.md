## [Version: v3.0.1-alpha.121] - 2026-11-26

Full Changelog: [v3.0.1-alpha.120...v3.0.1-alpha.121](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.120...v3.0.1-alpha.121)

> 重要提示

- 内置拓扑查询（`topo`）和执行诊断（`execution`）MCP 改为公开，系统诊断（`system-diagnosis`）MCP 保持非公开；三者均支持 public client OAuth2 和 personal client token。调用仍须满足相应的用户认证及资源权限要求。升级同步前请核对目标 stage 的公开性和授权策略。
- Backend 的 Jinja2 渲染器改为复用本地服务，须确保配置范围内有可用的回环监听端口，默认 `28150–28159`，无需对外开放。

**发布范围**

- Backend/Control Plane：插件依赖文件管理、插件进程依赖记录、Jinja2 配置渲染、默认直连管控单元接入点。
- Application/Frontend：内置 Wiki 阅读页、平台管理导航及权限控制。
- Installer/Deployment：MCP 产品清单及认证配置、Helmfile 最终 values 导出、Jinja2 和管控单元配置。

**新增功能**

- Backend 提供插件依赖文件创建、内容替换、适用范围更新、详情查询、分页列表和下载接口；由 File 维护独立的文件记录，支持按操作系统、CPU 架构及插件包版本限定适用范围。
- 插件 Process 支持保存实际依赖文件的记录 ID、目标路径、目标文件名及 MD5；常规进程信息更新不覆盖依赖记录。
- `system-diagnosis` MCP 新增系统配置只读查询，返回命中的 Backend 实例启动时加载的业务配置白名单，不返回凭据、连接端点或内部观测配置，也不代表所有副本配置一致。
- 新增内置中英文 Wiki 阅读页，支持 Markdown 渲染、目录和文档内部链接，复用现有 Web 登录流程。
- 新增平台管理导航，按 `platform_manage` 对 `system_config`、`scheduler_workflow` 和 `global_settings` 的授权范围展示菜单并校验页面访问；三个页面暂仅提供占位，不提供实际管理操作。
- 默认直连管控单元自动创建时支持同时创建下游接入点，供其他管控单元的 Proxy 连接。
- 支持独立配置 Redis Sentinel 认证密码，供 Backend、File、工作流和 Adminclient 连接使用。
- `execution` MCP 新增历史 Agent / Proxy 安装参数只读查询，不返回认证凭据，不创建或重试安装任务。历史记录并非完整请求快照，调用方须检查 `missing_fields` 和 `unavailable_operation_ids`，不能将缺失值当成上次的选择。

**功能优化**

- Agent 管理、Proxy 管理的菜单及页面标题简化为 Agent、Proxy。
- V3 插件和旧版 V2 插件的 Jinja2 配置渲染复用内嵌服务，支持并发请求，减少重复启动渲染进程的开销，并增加链路追踪和请求指标。
- Helmfile `render-values` 导出包含 Chart 及启用的子 Chart 默认值、模板生成值和用户覆盖值的最终 values，覆盖优先级与部署一致；不修改原始 Chart，也不部署到集群。

**缺陷修复**

- 修复 Helmfile 示例配置固定关闭 Jinja2 Trace 采样的问题；启用 Gateway 且未显式配置采样率时，Jinja2 跟随其他 Backend 组件启用采样。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式。
- 依赖文件记录、Plugin 依赖声明和 Process 实际依赖状态是独立对象。本版本提供文件管理接口及 Process 依赖记录存储能力，不包含 Plugin 依赖声明管理、依赖自动下发或应用流程；Backend 不提供依赖文件传输接口。

**组件依赖与升级前置条件**

- 使用插件依赖文件管理接口时，配套升级 Backend 与 File。创建及更新需 `plugin_operate`，查询及下载需 `plugin_view`，均按当前租户和插件可见范围校验。这六个接口已纳入 API Gateway 资源清单，须同步并发布后方可通过网关调用；资源不公开且不开放自助申请，调用方须通过应用认证并获得网关资源授权。
- 使用新版内置 MCP 须配套升级 Chart 和 apigw-sync 镜像，发布对应用户态网关资源并同步 MCP 定义；内置模式仍默认关闭，启用需 `apigwSync.mcp.enabled: true` 和 `spec_version: 2`。显式 stage 清单仍完全覆写内置清单，不会自动加入新工具。用户态系统配置查询的网关资源现明确要求用户认证，并须具备 `system_access` 和 `platform_resource/system_config` 的 `platform_manage` 权限。系统诊断仍仅面向获准的内部维护人员，其中全局配置查询可能返回敏感配置。
- 使用内置 Wiki 阅读页时，设置 `backend.config.wiki.mode: application`、`backend.config.wiki.application.prefixURL` 为用户可访问的 `/#/wiki/` URL 前缀，并开启 `application.config.wiki.enabled`；入口代理须保留部署子路径并将原文请求转发至 Application 的 `/wiki/`。原有 `/wiki/` 前缀仍可直接访问 Markdown，原文保持匿名、只读访问，不应包含敏感信息。
- `backend.config.networkUnit.defaultDirectUnit.accessPoints` 默认为空，仅在默认管控区域（ID 0）尚无直连管控单元时通过定时同步创建；已有单元及接入点不会自动更新。启用自动创建时单元名称不能为空，每个接入点须有名称且 cluster、file、data 通道各至少一个 `IP:端口` 地址，否则 Backend 启动失败；下游接入地址应使用 Proxy 接入端口，不能直接沿用本单元 Agent 的上游地址。
- Jinja2 可通过 `backend.config.jinja2x.portRange` 修改端口范围，端口取值须在 1–65535 且结束端口不小于起始端口；Chart 的 `traceSampleRate` 默认 `0`；使用 Helmfile 且 Gateway 启用时，未显式配置的采样率设为 `1`，显式配置保持优先。内嵌服务退出后下一次渲染自动重建，当次失败请求不会自动重试。
- Redis Sentinel 要求认证时，在 Backend 与 File 的 `externalRedis.sentinelPassword` 中填写 Sentinel 密码；数据节点密码仍使用 `externalRedis.password`。KMS 模式使用 global envelope 的 `redis.default.sentinel_password`，并覆盖配置文件中的 `redis.sentinelPassword`。
- Helmfile `render-values` 默认跳过依赖下载，Chart 须已包含所需依赖；使用远程 Chart 时须配置可访问的 Helm 仓库。导出的最终 values 可能含有凭据，不应直接分享。
