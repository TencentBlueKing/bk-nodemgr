## [Version: v3.0.1-alpha.123] - 2026-11-27

Full Changelog: [v3.0.1-alpha.122...v3.0.1-alpha.123](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.122...v3.0.1-alpha.123)

> 重要提示

- 配置策略接口不再接收或返回内部排序值 `priority`。Application 和 Backend 须在同一升级窗口切换，切换期间暂停配置策略编辑；新版 Application 向旧版 Backend 提交编辑请求会将排序值写为 `0`。回滚时也须成对回滚。
- 文档中心地址改为“URL 前缀 + 节点管理文档路径”；原来配置完整文档链接的环境须拆分配置，避免重复拼接路径。

**发布范围**

- Backend/Control Plane：历史插件安装参数查询、配置策略排序与接口字段调整。
- Application/Frontend：全局变量只读查询、定时任务执行详情及配置策略排序展示。
- Installer/Deployment：文档中心配置拆分、IAM 平台管理员角色与权限申请快捷组合。

**新增功能**

- 全局变量页面支持按变量名精确搜索、分页、刷新，以及查看和复制完整原始值。变量跨租户共享，包含自定义项；页面仅展示数据库保存值，不补齐默认值、不代表进程实际生效值，也不提供修改操作。自定义值可能包含敏感信息，须按需授予访问权限。
- 新增历史插件安装参数查询接口，可读取所选安装操作的主机、插件版本、自定义配置及部署规格，供新安装使用；仅支持 `install_plugin` 工作流，不执行安装、重试或修改历史任务，不包含页面自动回填。
- 新增 IAM V4 `platform_manager`（平台管理员）角色和 IAM V3“平台管理员”权限申请快捷组合，仅包含 `system_access` 与 `platform_manage`；平台资源范围以实际授权为准，不自动授予人员权限或全部平台资源权限。

**功能优化**

- 定时任务执行详情改为独立页面，支持切换实例、按步骤查看状态和耗时、查看执行日志及手动刷新；返回时重新打开对应工作流的执行历史。页面仍仅提供只读查询。

**缺陷修复**

- 普通编辑配置策略时保留原有排序；列表优先级序号由 Backend 返回，修正分页展示，并使插件配置策略排序预览加载当前业务的全部启用策略，不受当前列表页限制。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式，无需为本次控制面与页面更新升级主机上的 Agent 或插件。
- 历史插件安装参数来自保留的部署记录，并非原始请求的完整快照；记录丢失或字段缺失时返回对应标识。重新安装前须补全参数，并确认主机、插件版本及配置仍然有效。

**组件依赖与升级前置条件**

- 配套更新 Application、Frontend 和 Backend。配置策略调用方须移除对 `priority` 的依赖；列表展示改用 `priority_rank`，其值为筛选结果中从 `1` 开始的序号，禁用策略和详情响应不提供该值。显式重排与预览继续通过有序策略 ID 指定顺序；本次不需要数据库迁移。
- 全局变量查询需 `system_access` 及 `platform_resource/global_settings` 的 `platform_manage` 权限；定时任务详情沿用 `platform_resource/scheduler_workflow` 的 `platform_manage` 权限。历史插件安装参数查询需系统访问权限，以及历史工作流涉及的所有业务的插件历史查看和插件查看权限。
- 使用新增平台管理员授权入口前，同步对应 IAM 模型并配置人员及资源范围授权。IAM V3 须先注册 `0006` 中的 `platform_manage`，再同步更新后的 `0005` 常用操作组合；IAM V4 同步更新后的 `0004` 角色模板。已同步角色的环境回滚时，仅重跑旧 V4 模板不会删除新增角色，须先撤销其授权再删除角色。
- Application 配置 `front.bkDocsCenterURL` 现在表示文档中心 URL 前缀，新增 `front.bkDocsCenterNodemgrDocPath` 表示文档路径，默认 `/markdown/NodeMgr/UserGuide/Introduce/Overview.md`；前缀为空时文档链接保持为空。Helm 和 Helmfile 使用 `application.config.front` 下的同名字段；Docker Compose 新增环境变量 `BK_NODEMGR_APPLICATION_DOCS_CENTER_NODEMGR_DOC_PATH`。
