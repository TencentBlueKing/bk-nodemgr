## [Version: v3.0.1-alpha.84] - 2026-09-15

Full Changelog: [v3.0.1-alpha.83...v3.0.1-alpha.84](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.83...v3.0.1-alpha.84)

> 重要提示

- IAM v4 角色进一步拆分，原 Agent / Proxy 角色不再包含插件权限，管控区域创建权限独立授权。模型更新不会将已有授权转移到新角色，升级前需核对受影响用户的角色及资源范围。
- 部署策略 `Execute` 响应由 `trigger_id` 改为父 `workflow_id`，不提供旧字段别名。调用方需同步修改响应解析，并通过 `WorkflowList` 查询执行记录；旧文档中的 `WorkflowResult` 契约已移除，不提供该接口。

**发布范围**

- Agent / Proxy / Plugin: 历史任务鉴权与部署策略执行记录。
- Package: 共享制品定时同步、共享与同步状态、包上传和列表交互。
- Backend/Control Plane: IAM v4 角色与创建者授权、拓扑历史权限、部署策略执行记录查询与状态监控、etcd 服务发现。
- Installer/Deployment: IAM v4 模型更新工具、Alpine 容器运行依赖。

**新增功能**

- IAM v4 提供独立的 Agent、Proxy、Plugin、配置策略、拓扑和资源包管理或只读角色，并分离管控区域创建与管理权限；角色操作成员支持原地增删和授权维度调整，无需删除重建角色。
- 创建管控区域或管控节点后，为创建者授予对应资源的管理权限；IAM v4 授权有效期为 365 天，不自动续期。
- 包发布支持 `is_shared`，列表支持返回和筛选 `is_shared` / `is_synced`。多租户页面增加同步来源标记，`system` 租户上传非证书包时提供默认开启的共享选项。
- 非 `system` 租户每 10 分钟同步 `system` 租户的共享制品，覆盖 Agent、Proxy、Plugin、证书及工具包；同步副本标记为 `is_synced`。
- 部署策略执行按租户保存策略工作流及其关联的 Node / Plugin 子工作流，覆盖手工执行、定时执行和关联策略。新增 `WorkflowList` 分页查询与计数，支持按 workflow、策略、状态、操作人及操作时间过滤，后台同步父流程 dispatch 状态和完成时间。

**功能优化**

- 多租户虚拟用户查询按租户和登录名在本地缓存一分钟，减少重复访问用户管理服务。
- Alpine 服务镜像加入 `bash`，支持依赖 Bash 的运维脚本。

**缺陷修复**

- 节点工作流按已保存的业务与节点角色校验历史查看权限，避免仅依据请求筛选条件授权；修正授权范围与查询条件无交集时的列表和计数返回。
- 管控区域历史查询按区域历史权限包含其下级事件，修复误要求下级资源权限及空授权交集处理问题。
- 修复 IAM 权限申请中资源名称缺失、空白弹窗、切换页面后旧鉴权结果覆盖新状态，以及授权更新后仍显示无权限的问题。
- 插件包列表使用查看权限而非管理权限筛选；权限未就绪或没有可查看插件时不发送无过滤查询。修复插件上传类型展示和未上传文件时关闭侧栏仍要求确认的问题。
- 修复包版本操作在权限不足时因错误码映射触发 panic 的问题，保留权限申请信息。
- 修复 etcd 服务发现兜底逻辑的重复写入，避免无变化时持续增加 MVCC revision 和存储占用。

**Agent / Plugin / Package compatibility**

- 本版本不改变 Agent / Proxy、Plugin 或 Package 包格式，继续沿用 alpha.82/83 的租户隔离存储、下载路径和组件配套要求。
- 共享制品同步保留租户自有包，已同步副本的 MD5 未变化时跳过更新；取消源制品共享不会自动删除已有副本。发布 API 未传 `is_shared` 时默认为 `false`。

**组件依赖与升级前置条件**

- 更新 IAM v4 模型前执行 `--dry-run`，核对角色操作成员删除及新增角色授权。IAM 拒绝成员删除时更新会停止，已完成操作不自动回滚；重跑或回滚前检查远端模型与授权。模板不再包含部署策略操作，但不会自动删除已注册操作或旧 `policy_manager` 角色。
- IAM v4 初始化与运行时仍独立开启，升级不自动切换鉴权版本或迁移 IAM v3 授权。创建者授权失败不撤销已创建资源，需检查日志并补充授权。
- 配套升级 Application、Backend 与 File Service，同步 API Gateway 定义及 `Execute` 调用方，验证包状态与权限，以及 `POST /api/v3/deploy_policy/workflow/list`。回滚需同步恢复调用方的响应解析，不能混用新旧执行 ID。
- Backend 需能创建并读写 `deploypolicy_workflow_{tenantID}` collection 及其唯一索引，并读取父 operation 以同步状态。升级后验证后台状态更新；缺少状态的旧记录会自动补齐，未完成记录的 operation 缺失超过一分钟后标记为 `failed`。
- 共享制品同步依赖 Backend 调度和配套 File Service；升级前核对 `system` 租户的共享范围，升级后检查非 `system` 租户的同步任务及副本。
- **待确认**: 目标 IAM v4 环境的角色变更、重新授权及回滚方案。

**已知问题**

- 父流程 `success` 仅表示 dispatch 成功，不代表子流程部署完成。状态异步更新，子流程结果需通过现有 Node / Plugin workflow API 查询并满足各自权限；父流程可见不授予子流程访问权限。
- dispatch action 不自动重试，也不提供部署策略 workflow 的 retry 或 terminate API；再次 `Execute` 会创建新的执行。dispatch 失败不会终止已发起的子流程，串联策略前需由调用方确认子流程结果。
