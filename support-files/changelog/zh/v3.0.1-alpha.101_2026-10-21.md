## [Version: v3.0.1-alpha.101] - 2026-10-21

Full Changelog: [v3.0.1-alpha.100...v3.0.1-alpha.101](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.100...v3.0.1-alpha.101)

**发布范围**

- Backend/Control Plane：支持 Windows firewall 部署配置、旧版 V2 插件冲突检查，以及 Node workflow 并发限制和重试退避。
- Plugin/Package：V3 插件包支持声明安装过程的磁盘 IO 限速；包上传和发布增加服务端权限前置检查。
- Installer/Deployment：Windows Agent 安装前可按配置应用 firewall 规则；Installer 支持安装包磁盘 IO 限速；KMS 部署的 IAM/API Gateway 同步 Job 从加密配置获取应用凭证。
- Topology：优化拓扑操作记录筛选与操作人信息。

**新增功能**

- V3 插件 `project.yaml` 可选配置 `installDiskIoLimit`（MB/s），用于限制安装或升级过程中处理 tgz 包的逻辑读写速度。未配置或设为 `0` 时不限速；V2 插件包忽略该字段。
- 插件安装 API 可选择启用旧版 V2 插件运行状态检查。对于声明存在旧版冲突的 V3 插件包，若目标主机上同名 V2 插件正在运行，安装会被阻止；启用该检查时，需先停止冲突的 V2 插件。
- Windows Agent 部署可配置 `gse`、`nodemgr` firewall features 及允许访问的 CIDR。features 为空时不管理 firewall 规则；单个 IPv4/IPv6 地址分别使用 `/32` 或 `/128` CIDR 表示。
- Node 安装、升级、重配、重启、卸载、分配 Proxy Unit 六类 workflow 支持独立 Global Settings `oper_node_<operation>_max_concurrency_num`，operation 分别为 `install`、`upgrade`、`reconfig`、`restart`、`uninstall`、`assign_proxy_unit`，默认值均为 `200`，且须为正整数。并发限制按单个 trigger 生效，不限制多个 workflow 的合计并发。
- adminclient 新增 `bkapp code`、`bkapp secret` 子命令，从 KMS global envelope 获取应用凭证，供 Helm 的 IAM V3/V4、API Gateway 同步 Job 使用；非 KMS 部署继续使用原有凭证配置。

**功能优化**

- Topology 操作记录支持按管控区域、管控单元、类型和操作人筛选，并优化操作人展示及筛选后的分页行为。
- Node Action 失败重试由固定延迟改为指数退避并附加随机抖动；超时和重试次数不变，部分失败动作的后续重试及最终失败返回可能等待更久。
- 合并 ORM 和 workflow 操作实例数据的字段写入，并合并同名全局配置的并发读取，减少重复存储请求。

**缺陷修复**

- 修复 Windows SSH 安装失败时底层错误原因丢失、下载服务器配置错误信息标签不正确、deploy policy scope type 错误信息不正确，以及网络区域 ID 无效时错误返回不正确等问题。
- 修复拓扑操作记录的操作人记录不准确问题。
- 包上传和发布入口在解析请求和执行文件操作前检查对应包类型的 `package_type_upload` 权限，未通过鉴权时终止操作。
- 修复 Agent/Proxy 运维信息更新因已有主机的节点角色不匹配而被拒绝的问题；保留主机存在性校验和业务操作鉴权。
- 修复非法 tracing exporter 类型被误报为缺少类型的问题，保留底层校验错误，便于定位启动配置问题。

**Agent / Plugin / Package compatibility**

- `installDiskIoLimit` 为可选配置；未配置或设为 `0` 时维持不限速行为，旧版 V2 插件包不使用该配置。
- 只有在 V3 插件包设置正数 `installDiskIoLimit` 并生成带 `--diskio-limit` 的安装/升级脚本时，执行该脚本的 Installer 才需要支持此参数；否则不要求为该配置升级 Installer。
- 管控单元未设置 `firewall` 时继承部署默认配置；显式设置空对象 `{}` 时禁用 firewall setup。有效配置启用后，规则按所选 features 及允许的 CIDR 应用。
- Node 并发配置在创建 trigger 时固定，修改只影响后续创建的 trigger；重试沿用原 trigger。
- 包上传、发布的请求与成功响应字段不变；此前未被权限检查阻止的请求现在须通过对应包类型鉴权。

**组件依赖与升级前置条件**

- 对启用了 V2 插件冲突检查且命中冲突的主机，安装前须停止正在运行的同名旧版 V2 插件。
- 使用 `installDiskIoLimit` 时，部署环境中的 Installer 需支持 `--diskio-limit`；数值须为非负 MB/s，负值或非数值会导致插件包导入校验失败。
- Windows firewall 规则由 Installer 在安装前应用；请先确认部署配置中的 features 与 CIDR 符合预期。未设置 features 时不会管理 firewall 规则。
- 升级前确认包上传、发布操作人员具有对应 `package_type` 资源的 `package_type_upload` 权限；backend 鉴权服务不可用时，这些操作将终止。
- KMS 部署需同时升级 chart 与相关镜像，确保同步 Job 使用的镜像包含 `bk-nodemgr-adminclient bkapp`。启用 KMS 的同步 Job 要求 `backend.enabled: true`，可读取 KMS global envelope，并通过 `BK_NODEMGR_KMS_PRIVATE_KEY_GLOBAL` 注入私钥；Helm 从 global KMS Secret 的 `privateKey` 获取该值。
