## [Version: v3.0.1-alpha.83] - 2026-09-14

Full Changelog: [v3.0.1-alpha.82...v3.0.1-alpha.83](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.82...v3.0.1-alpha.83)

> 重要提示

- IAM v4 模型初始化与运行时鉴权仍默认关闭，升级不会自动从 IAM v3 切换到 v4，也不会迁移已有授权。启用模型初始化仍不迁移用户组授权或资源范围，完成模型注册后需验证授权与权限申请流程。
- Backend 的包查询、状态管理和事件查询改由 File Service 提供。升级与回滚需配套切换 Backend 和 File Service，避免新版 Backend 调用旧 File Service 中不存在的接口。
- Helm 包初始化 Job 默认启用 `--set-as-default`，会启用选中的 Agent、Proxy 和 Plugin 包并改设默认版本。执行前核对输入包及顺序，不能将选择结果视为按版本号选取的最新版。

**发布范围**

- Agent / Proxy: 初始化包启用与默认版本设置。
- Plugin: 插件列表、进程详情、安装版本选择与 Relay 工作目录。
- Package: File Service release 管理、包事件查询和初始化请求超时。
- Backend/Control Plane: IAM v4 回调与权限模型、历史任务查看权限、任务详情与日志页面。
- Installer/Deployment: IAM v4 Helm 初始化和配置、默认包初始化流程。

**新增功能**

- IAM v4 初始化补齐本地业务资源 `biz`、32 个操作和四个角色，支持有限更新及 `--dry-run` 预检查。
- IAM v4 资源回调支持业务、管控区域、管控节点、包类型和包的列表与详情查询，补齐 API Gateway 注册、租户传递及独立的 v4 响应协议。
- File Service 新增 release 查询和管理、包事件查询接口，统一承接 Agent、Proxy、Plugin 的启停用与默认版本设置，以及各类包的 release 元数据删除。
- 初始化脚本支持发布后按平台启用并设为默认包；手工运行时通过 `--set-as-default` 开启，证书和工具包仍只执行上传与发布。
- 新增按租户每分钟查询已启用插件包的定时任务，补齐缺失的默认插件记录；不改变默认包版本，也不向主机部署插件。

**功能优化**

- 初始化包上传、发布及状态操作的请求超时统一延长至 30 分钟，为大包和较慢的发布操作预留等待时间。
- Relay 未显式指定工作目录时，按部署环境隔离为 `/tmp/bknm/{deploy_env}/relay`，Windows 使用 `c:/tmp/bknm/{deploy_env}/relay`，减少不同环境共用目录造成的冲突。

**缺陷修复**

- Agent、Proxy 和 Plugin 的历史任务、操作实例及日志查询使用对应的历史查看权限，不再误用资源查看或操作权限。
- 修复任务详情跨页全选后的批量重试、终止及 IP 复制范围不完整问题；日志页增加服务端分页和筛选，节点任务跳转携带目标 IP 定位条件。
- 修复切换业务后插件列表未刷新、进程列表第二页起主机信息缺失、安装时默认版本被其他插件版本干扰的问题；升级表格支持移除多余主机行。
- 修复 IAM v4 Helm 配置未输出到 Backend 配置的问题，并区分回调凭据错误与 token 服务故障。
- 修复禁用 IAM 与跳过鉴权混用的问题：禁用版本的直接 IAM 调用及回调认证返回错误，不再放行；仅当 IAM v3/v4 运行时均关闭时，Backend 才跳过业务鉴权。
- 修复拓扑页面创建权限判断：创建管控区域按无资源权限校验，创建管控节点按所属管控区域校验；权限申请流程及 IAM v3/v4 权限模型保持不变。
- 修正初始化脚本的 Proxy/Server 发布地址，统一使用 `/api/v3/publish/release/proxy`。

**Agent / Plugin / Package compatibility**

- 本版本不涉及 Agent / Proxy、Plugin 与 Package 包格式变更；继续沿用 alpha.82 的租户隔离存储与下载路径要求。
- Relay 显式配置的 `WorkspaceFileGroupFullPath` 保持不变，不会自动获得环境隔离。重新部署前检查共享路径，未设置部署环境时默认使用 `dev`。
- IAM v4 回调使用字符串 `method`、顶层 `requires` 和独立的 `data` / `error` 响应，不复用 IAM v3 回调协议；自定义调用方需同步调整。

**组件依赖与升级前置条件**

- IAM v4 初始化通过 `iamV4.enabled` 开启，运行时通过 `backend.config.iamV4.enable` 独立开启；启用 v4 运行时前关闭 v3 运行时。配置 `backend.config.iamV4` 的 `bkiam` 网关与应用凭据，并确保 `iamV4.system.clients` 包含该应用编码。
- 配置可访问的 `iamV4.provider.host` 和 `/api/v3/iam/v4/resource` 回调路径；回调使用 `bk_iam` 与系统 token 做 Basic Auth，多租户请求必须携带 `X-Bk-Tenant-Id`。
- IAM v4 Helm Job 在安装和升级后执行；单租户只初始化 `default`，多租户只初始化 `system`，不会遍历租户。使用包含 v4 迁移工具的 Backend 镜像，执行前先对目标租户运行 `--dry-run`。
- IAM 模型祖先链、操作资源绑定、角色成员删除或维度变更冲突会停止迁移。Job 失败会阻塞 Helm 发布，已写入模型不会自动回滚；重跑或回滚前检查远端状态。向已有角色追加操作可能使原授权范围内的用户获得新增权限，须先确认影响。
- 默认包按处理顺序选择：Agent 取最后一个输入包，Proxy 与 Server 共用一组；Plugin 按入口类型及插件名分组，取最后一个上传成功的包。目标发布失败不回退到前一个包，缺失平台不由旧包补齐，部分成功不自动回滚；执行后检查各平台默认版本和失败清单，并为 Helm 等外层等待设置足够时间。
- 核对 Backend 到 File Service 的连接、认证与租户配置，并验证包查询、启用、默认版本和事件记录；多租户包初始化需启用 File JWT 认证并使用匹配的密钥。
- 默认插件记录补齐依赖 Backend 能查询对应租户已启用的插件包；回滚该功能前，需按租户禁用或删除对应的定时工作流。
- **待确认**: 目标 IAM v4 部署版本的联调结果、存量 IAM v3 授权切换与回滚方案。完成确认前保持现有鉴权配置。

**已知问题**

- 部署策略 `ensure_absent` 仅支持更新保存及列表返回，默认 `false`。执行器尚未实现反向删除或卸载；即使设为 `true`，仍执行现有逻辑，不能用于清理插件或配置。
