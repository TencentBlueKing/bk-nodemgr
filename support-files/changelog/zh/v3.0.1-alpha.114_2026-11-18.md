## [Version: v3.0.1-alpha.114] - 2026-11-18

Full Changelog: [v3.0.1-alpha.113...v3.0.1-alpha.114](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.113...v3.0.1-alpha.114)

> 重要提示

- `bk_token` 登录默认改用 `/open/bk-tokens/userinfo/`，不再按租户模式自动选择接口。仍依赖 `/accounts/get_user/` 的单租户环境升级时，必须设置 `application.config.bkSaaS.bkLogin.useLegacyAPI=true`；该兼容模式不支持多租户。`bk_ticket` 行为不变。

**发布范围**

- Backend/Control Plane：旧版 V2 插件进程分页与兼容查询、节点与插件执行诊断、插件子配置投影批次编排。
- Application/Frontend：登录接口选择、配置策略管控单元选择与下拉搜索修复。
- Installer/Deployment：登录兼容配置、API Gateway 执行诊断 MCP 与容器本地 Trace ID 日志检索脚本。

**新增功能**

- 新增旧版 V2 插件进程查询 API `POST /api/v3/process/list_v2`，支持分页、仅计数及精确／模糊筛选，返回进程状态与配置详情；查询范围按调用方的业务级 `plugin_view` 权限收敛。查询明细时每页最多 500 条，仅计数时返回空 `items`。
- 新增用户态节点与插件执行诊断 API 及 `execution` MCP 服务，可查询工作流、操作、执行实例和步骤日志；按调用用户权限限制查询范围，不提供重试、终止或修改操作。
- 新增 `/bk-nodemgr/script/ops/trace.sh <traceid>`，可按 Trace ID 检索当前容器的本地日志，输出文件名、行号及日志原文，无需日志 exporter。

**功能优化**

- 旧版 V2 插件进程兼容查询与状态同步改为分批读取主机或进程记录，兼容查询保持原有返回结构。
- V3 插件子配置投影支持在同一执行主机上按批次准备多个源插件，并按输入顺序下发目标配置；独立批次之间不保证串行执行。

**缺陷修复**

- 修复 Agent 与插件配置策略切换管控区域后管控单元被置空的问题：切换后默认选择“不限”，并在提交时校验空值，避免将空字符串作为管控单元 ID 提交。
- 修复业务、管控区域与管控单元下拉搜索匹配异常，支持按名称或部分 ID 搜索；Agent 配置策略编辑时保留管控单元“不限”值。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式。
- `POST /api/v3/process/list_v2` 仅查询旧版 V2 插件进程记录，不替代当前 V3 插件进程查询；既有 API 路径保持不变。节点与插件工作流查询新增部署策略筛选与关联策略信息字段。

**组件依赖与升级前置条件**

- 使用默认 `bk_token` 登录接口时，需配置 `application.config.bkSaaS.bkLogin` 下可访问该接口的 `endpoints`、`appCode`、`appSecret`，以及 `authMode=un` 所需的 `user` 或 `authMode=at` 所需的 `accessToken`；`loginURL` 仅用于浏览器跳转，不能替代 API 网关地址。旧版单租户接口的兼容开关见重要提示。
- 通过 API Gateway 调用新增查询 API 前，需同步并发布对应网关资源；仅升级 Backend 不会开放网关接口。旧版 V2 进程查询需具备目标业务的 `plugin_view` 权限；执行诊断还需网关应用与用户认证、资源访问授权、`system_access` 及相应的 Agent、Proxy 或插件历史查看权限。`execution` MCP 服务默认未启用，使用前需在网关中启用。
- Trace 日志脚本随本版本镜像交付，仅接受 32 位小写十六进制 Trace ID，检索当前容器 `/bk-nodemgr/log` 中已落盘且带对应 Trace ID 的日志，不跨 Pod 查询；排查多 Pod 链路时需分别进入相关容器执行。
