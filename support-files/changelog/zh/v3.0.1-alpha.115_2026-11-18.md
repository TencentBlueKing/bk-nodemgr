## [Version: v3.0.1-alpha.115] - 2026-11-18

Full Changelog: [v3.0.1-alpha.114...v3.0.1-alpha.115](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.114...v3.0.1-alpha.115)

> 重要提示

- 用户名兼容不再由租户模式决定。蓝鲸平台 7.2 升级节点管理时，必须同时设置 `backend.config.userManager.useLegacyUsername=true` 和 `application.config.userManager.useLegacyUsername=true`；蓝鲸平台 7.3 的单租户与多租户环境均应保持默认值 `false`。`true` 仅支持单租户模式。
- NodeMan 离线迁移工具仅适用于蓝鲸平台 7.2 升级至 7.3 时，将 NodeMan 的主插件进程及主配置回填到 NodeMgr；不自动迁移 Agent 或插件包。导入不删除已有数据，但会覆盖匹配的进程与配置记录。

**发布范围**

- Backend/Control Plane：用户标识解析与旧版用户名兼容。
- Application/Frontend：Application 用户标识解析与旧版用户名兼容。
- Installer/Deployment：用户名兼容配置及 NodeMan 主插件进程离线迁移工具。

**新增功能**

- 新增 NodeMan 主插件进程离线导出工具，按租户、业务和插件生成可由 `mongosh` 导入的文件，支持选择分组回填旧版 V2 插件进程记录与主配置。

**缺陷修复**

- 修复单租户模式直接将 `login_name` 当作 `bk_username` 的问题：默认通过用户管理查询当前租户的虚拟用户映射，支持蓝鲸平台 7.3 单租户环境；蓝鲸平台 7.2 可显式启用旧版用户名兼容。

**Agent / Plugin / Package compatibility**

- 本版本不变更 Agent、Plugin 或 Package 格式，不调整既有业务 API 路径及请求／响应结构。
- 迁移工具仅回填主插件进程和主配置记录，不替代 Agent 升级或插件包迁移。

**组件依赖与升级前置条件**

- 蓝鲸平台从 7.2 升级至 7.3 时，必须同步将 Backend 和 Application 的 `userManager.useLegacyUsername` 切换为 `false`。为节点管理应用开通用户管理 `GET /open/tenant/virtual-users/-/lookup/` 调用权限，并正确配置两个服务的 `userManager.endpoints`、应用凭证和请求租户标识；单租户使用 `default` 租户。查询失败、无权限或用户映射不存在时返回错误，不回退为 `bk_username = login_name`。
- `userManager.useLegacyUsername` 与既有的 `application.config.bkSaaS.bkLogin.useLegacyAPI` 相互独立，不能替代登录接口兼容配置。Helm／Helmfile 需同步配置两个服务；Docker Compose 模板默认值同为 `false`，部署到蓝鲸平台 7.2 前须同步改为 `true`。
- 迁移导出需在原 NodeMan 的 Django 环境中连接原数据库执行；将导出文件转移至 NodeMgr 后，确认目标数据库，再使用 `mongosh` 导入。导入采用 `upsert`，只新增或更新文件中的记录，不删除其他已有数据。
