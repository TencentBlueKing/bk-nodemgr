## [Version: v3.0.1-alpha.107] - 2026-11-10

Full Changelog: [v3.0.1-alpha.106...v3.0.1-alpha.107](https://github.com/TencentBlueKing/bk-nodemgr/compare/v3.0.1-alpha.106...v3.0.1-alpha.107)

> 重要提示

- 加密套件默认保持 `CLASSIC`。切换至 `SHANGMI` 或切回 `CLASSIC` 均不迁移历史密文；另一套件保存的临时主机凭据无法复用，安装时需重新录入。切回 `CLASSIC` 后，SM4 凭据仍不可读；复用尚未过期的原 AES 凭据还需保留原 `encryptKey`。
- 资源包操作历史按资源包类型校验 `package_history_view` 权限。启用 IAM 的环境升级时需同步权限模型及相应授权；IAM V4 已有该 Action 绑定 `package` 时，需显式替换为 `package_type`，再同步角色并核验新维度授权，不能仅执行普通 upsert。替换可能清除已有权限，旧授权不会自动迁移。
- 存活插件进程同步 URL 从 `/api/v3/sync/gse/plugin/process/info`、`/api/v3/sync/gse/plugin/process/info/all` 改为 `/api/v3/sync/gse/plugin/process/info/alive`、`/api/v3/sync/gse/plugin/process/info/alive/all`，旧路径不再注册，直接调用方需同步调整。
- IAM V4 对无资源鉴权的放行结果增加本地 5 分钟缓存，撤权后可能继续放行至缓存过期；拒绝结果和 IAM 错误不缓存，新增授权不会受到拒绝缓存延迟。带资源的鉴权不使用该缓存。

**发布范围**

- Backend/Control Plane：国密凭据加密与出站 TLCP、插件兼容部署及配置渲染、部署策略归属制品清理、插件进程状态同步、GSE 操作身份、资源包历史鉴权与 IAM V4 缓存。
- API Gateway/MCP：拓扑只读查询切换至用户态开放 API。
- Application/Frontend：加密套件适配、租户与用户维度的浏览器本地缓存隔离、未分配管控区域的交互限制。
- File：资源包元数据缓存及多副本缓存失效同步。
- Installer/Deployment：插件多主配置、子配置保留与重建控制、国密部署配置及 File 服务 Redis 接入。

**新增功能**

- 插件安装与升级支持多份主配置文件，覆盖 V3 与旧版 V2 插件；同一插件的主配置共用自定义渲染上下文，配置文件名须唯一。
- 支持 `SHANGMI` 国密套件：SM2 加密传输登录凭据、SM4-GCM 加密保存临时凭据；新增统一公钥接口 `Cipher_GetCurrentPublicKey`，调用方按 `key_type` 选择算法。出站 API Gateway 客户端可单独启用 TLCP。
- `ensure_absent` 部署策略支持清理归属于该策略的插件包部署及子配置，覆盖插件包、插件包投射和两类子配置 spec；包括旧部署范围或旧承载主机上的匹配制品，不按版本或运行状态过滤。
- 新增已停止插件进程信息同步，支持指定主机、租户内全量触发及默认每 10 分钟的定时同步；向 GSE 重新核实本地 `stopped` 记录，Agent 离线或 GSE 不再上报时标记为 `unknown`。接口返回 `trigger_id` 仅表示任务已提交，需查看执行结果。

**功能优化**

- File 服务的资源包元数据查询使用本地缓存，并通过 Redis 标记在同一租户的多个 File 副本间同步写入失效；失效标记写入失败时，已有缓存按 1 分钟 TTL 过期。
- 兼容模式下，V3 插件升级同时将旧版 V2 插件对齐至目标版本；运行版本为空或不匹配时，在安装前停止旧进程并安装目标版本，升级时保留原有子配置。
- 插件安装器支持按需保留或重建子配置；本次下发的同名配置优先于保留文件。常规 V3 API、预置插件及部署策略仍重建子配置，不统一改为保留。
- V3 插件包配置模板的 `filePath` 可省略或为空，自动填入主配置目录 `etc` 或子配置目录 `etc/<plugin_name>`；显式填写时仍须匹配固定目录。
- 浏览器本地缓存按“租户 + 登录用户”隔离，避免不同租户下同名用户的偏好数据串扰。
- 拓扑 MCP 的 11 项只读查询绑定至 `/api/v3/open/topo/*` 用户态 API，沿用用户身份、系统准入与资源权限检查，不提供写操作；使用该 MCP 的环境需同步 API Gateway 资源及 MCP 定义。

**缺陷修复**

- 修复旧版 V2 插件包及外部插件包上传结果中的插件名称被错误填为上传文件名的问题，正确保留插件包名称。
- 统一管控区域页面路径：`workarea`、`workarea-detail` 分别改为 `networkarea`、`networkarea-detail`；已有书签及外部页面链接需同步更新，旧路径不再注册。
- 修复插件自定义配置 context 中的模板表达式未先渲染、导致配置内容不符合预期的问题，覆盖 V3 与旧版 V2 插件。
- 修复插件进程及文件操作误用安装登录用户的问题：GSE 操作默认使用 Unix-like 的 `root`、Windows 的 `system`；安装登录用户及模板 `account` 语义保持不变。
- 修复资源包操作历史列表与计数缺少权限范围过滤的问题，仅返回获授权资源包类型的记录。
- 限制未分配管控区域在页面中的详情访问、拓扑选择、管控单元创建与分配，避免将其作为普通管控区域操作。

**Agent / Plugin / Package compatibility**

- 旧 RSA 公钥接口保留；仅支持 RSA 的调用方须使用 `CLASSIC`，启用 `SHANGMI` 前需适配统一公钥接口及 SM2。套件切换后需刷新已打开的凭据输入页面，重新获取公钥。
- V2 兼容升级需要目标版本对应的旧版插件包，版本不匹配时会停止旧进程，不是无中断升级。
- `ensure_absent` 尚不支持 `specify_plugin` 或 Agent/Proxy。子配置删除要求插件进程存活；任务提交不代表清理完成，需查看执行结果。不要为同一制品配置正反方向相冲突的策略。

**组件依赖与升级前置条件**

- File 服务新增 Redis 连接配置与启动连通性检查。Helm 使用内置 Redis 或 `externalRedis` 配置；自行维护配置的部署需补齐 File 服务 `redis` 配置，连接不可用时服务无法启动。
- 插件主配置回调由单文件响应改为 JSON 文件列表，Backend 与插件安装器（V3/V2）需配套升级，避免新旧回调格式不兼容。
- 使用国密能力需同步升级 Backend、Application 与 Frontend，并通过 `backend.config.cryptoType: SHANGMI`（Helm）或 `BK_NODEMGR_BACKEND_CRYPTO_TYPE=SHANGMI`（Docker Compose）启用；默认 `CLASSIC` 保持原有 RSA/AES 行为。
- TLCP 需对端支持该协议，并为对应客户端配置 CA、签名证书/私钥及加密证书/私钥，证书文件需挂载至服务容器；不配置加密证书对时保持标准 TLS。TLCP 仅支持出站客户端，不包含服务端监听、基础设施连接或 JWT 算法替换。
- IAM V4 绑定替换、角色恢复及授权检查步骤见 [权限模型迁移说明](https://github.com/TencentBlueKing/bk-nodemgr/blob/v3.0.1-alpha.107/support-files/bkiamv4/README.md#显式替换-action-绑定)。
