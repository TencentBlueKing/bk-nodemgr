# tracing

## 设计意图
提供基于 OpenTelemetry 的分布式追踪功能。解决多服务环境下统一追踪管理、链路传播和性能监控的核心问题。

## 功能边界
1. 此包负责：
   - 管理多个服务的 OpenTelemetry 追踪实例
   - 提供统一的追踪器生命周期管理
   - 支持多种追踪导出器（stdout、OTLP）

2. 此包不负责：
   - 具体的业务埋点和追踪策略
   - 追踪数据的存储和分析

## 设计考量
采用 Handler-Service 双层架构，Handler 管理全局追踪器实例，Service 提供单服务追踪能力。这种设计既支持多服务独立管理，又避免了全局状态污染，同时确保了线程安全和优雅关闭。

## 使用限制
1. 每个服务名只能创建一个追踪实例，重复创建会返回现有实例
2. 采样率必须在 0.0-1.0 范围内，建议生产环境谨慎设置
3. OTLP 导出器需要正确配置端点和认证信息

## 演进方向
1. 支持更多导出器类型（如 Jaeger、Zipkin）
2. 增加动态配置和热更新能力
