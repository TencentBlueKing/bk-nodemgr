# retrier

## 设计意图
本包主要是为了解决在执行某些操作时可能会遇到的临时性错误，通过重试机制来提高操作的成功率。
例如，在网络请求、数据库操作等场景中，可能会因为网络不稳定、服务端负载过高等原因导致操作失败。通过重试机制，可以在一定程度上缓解这些问题，提高系统的健壮性。

## 功能边界
1. 此包负责：
   - 支持多种重试策略，如指数退避、固定间隔等。
   - 支持自定义重试条件和最大重试次数。
   - 支持重试时的回调函数，可以在每次重试前后执行自定义逻辑。
2. 此包不负责：
   - 处理具体的业务逻辑。
   - 提供具体的错误处理机制。

## 设计考量
1. 重试是一种较为常见的错误处理策略，而且重试的实现往往大同小异，因此将其抽象成一个通用的包，可以提高代码的复用性和可维护性。
2. 针对不同的场景，可能会需要不同的重试策略，因此提供多种策略供用户选择，可以提高包的灵活性和适用性。

## 使用限制
1. 请确保在使用本包时，操作是幂等的，即多次执行同一操作不会产生副作用。
2. 请确保在使用本包时自行记录错误日志，以便后续排查问题。本包内嵌的日志记录功能仅供参考，不能替代业务系统的日志记录。

## 演进方向
1. 支持更多的重试策略，如随机退避。
2. 支持更多的重试条件，如网络异常、服务端异常等。
