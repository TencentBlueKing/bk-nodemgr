# errf

## 设计意图
提供统一的错误码管理和错误处理机制，实现错误信息与HTTP状态码的映射，便于API错误响应的规范化处理。

## 功能边界
1. 此包负责：定义标准错误码常量、提供错误的封装与解封装功能、维护错误码到HTTP状态码的映射
2. 此包不负责：具体业务逻辑的错误处理、错误的日志记录和持久化

## 设计考量
采用错误码和错误信息分离的设计模式，通过`errors.Join`进行简单封装，便于错误传递和HTTP响应统一处理。错误码使用38号段+5位数字的规则，保证系统错误码的唯一性和可识别性。

## 使用限制
1. 错误封装(`ErrWrap`)和解封装(`ErrUnwrap`)仅支持单层操作，不建议嵌套使用
2. 新增错误码时必须同时更新HTTP状态码映射表
3. 特殊错误码(如3830403-未授权)为内部保留，请勿覆盖

## 演进方向
1. 增加错误消息的国际化支持
2. 扩展错误码分类，支持更细粒度的错误场景区分
