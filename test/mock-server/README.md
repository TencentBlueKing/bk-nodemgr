# mock-server

## 设计意图

Mock Server 用于在测试环境中模拟第三方服务（如 CMDB）的 API 接口，解决测试环境依赖外部服务的问题。通过统一的架构设计，支持快速添加新的 Mock API，提高测试环境的独立性和可控性。

## 功能边界

1. 此包负责：
   - 模拟第三方服务的 API 接口
   - 提供测试数据响应
   - 管理 Mock API 的路由注册
   - 测试数据的存储与管理
2. 此包不负责：
   - 真实第三方服务的业务逻辑
   - 生产环境的服务调用

## 设计考量

采用分层架构设计，与项目主服务保持一致：
- **Service 层** - 管理服务生命周期，启动服务器（basic）
- **Router 层** - 统一通过 `Load` 函数注册路由，与 `internal/backend/router` 保持一致
- **Storage 层** - 使用内存存储模拟数据，支持线程安全访问
- **Config 层** - 支持 YAML 配置文件，便于测试环境配置

通过接口抽象和统一的路由注册模式，便于扩展新的 Mock API，同时保持代码风格的一致性。

## 扩展方式

### 添加新的 Mock API 模块

**模块目录**
   ```
   test/mock-server/router/cmdb/
   ├── router.go      # 路由注册
   ├── storage.go     # 存储
   ├── helper.go      # 该组件专属的响应格式封装, 辅助函数等
   ├── types.go       # Config、常量、错误码
   └── handler.go     # 业务处理逻辑
   ```
   
**注意**：
- 不要复用 cmdb/helper.go，每个组件的响应格式应独立定义
- 路由注册时必须使用 `rg.Group("/${mock-server-name}")` 创建组件路由组，确保路由前缀统一

参考实现：`router/cmdb/`

## 使用限制

1. Mock Server 仅用于测试环境，不应在生产环境使用
2. 测试数据存储在内存中，服务重启后数据会丢失
3. 所有路由必须通过 `Load` 函数注册，保持统一入口
4. 同一组件内的响应格式需保持一致（使用该组件的 helper.go），但不同组件之间可以有完全不同的响应格式
5. 所有 Mock API 路由必须遵循 `${mock-server-name}/xxxx` 前缀格式，确保路由命名规范统一
