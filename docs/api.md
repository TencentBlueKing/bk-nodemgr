## API 设计规范

### 分级规则

/api/{version}/{service}/{resource}/{method}

1. /api
   用于区分服务接口和静态资源请求，以便做权限拦截等处理。

2. /{version}
   用于区分接口版本，例如：v1，v2，v3等。此版本号用于标识接口的不同版本，方便向后兼容和迭代。

3. /{service}
   用于区分服务。每个 API 请求都是通过一个特定的服务进行处理的，常见服务有：
   - auth：认证服务，处理权限验证等。
   - sync：同步服务，处理同步相关请求。

4. /{resource}
   用于区分资源。每个 API 请求都是针对某个资源进行处理的，常见资源有：
   - user：用户资源。
   - plugin：插件资源。
   - host：主机资源。

5. /{method}
   用于区分行为。每个 API 请求都是针对某个资源进行的某个行为，常见行为有：
   - get：获取资源。
   - post：创建资源。
   - put：更新资源。
   - delete：删除资源。
   - patch：部分更新资源。
   - upload：上传资源。
   - download：下载资源。
